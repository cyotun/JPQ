# 本地识别适配与真机测试

2026-10-11。用户要求完成完整版，并已连接 USB 手机，授权安装、操作记牌器与大掼蛋进行测试。本文件是开发记录，不是完成验收声明。

## 已接入

- 本地 LiteRT CPU 牌面检测、随包中文 OCR、RGBA 采集、letterbox 坐标转换、28 类红黑点数及大小王、NMS，无逐帧云端识别或截图上传。
- 按参考脚本的方法实现叠放手牌向上搜索；状态包含大厅、新局、贡牌、队友展示、结算和不可用。
- 四帧稳定确认；空区域与未观察区域分开；稳定显示去重、观察到清空后同牌再次出；整手牌归属，不在列边界切开顺子。
- 仅完整 27 张初始手牌及观察到新局边界才初始化。自己手牌减少需要可见出牌证据。颜色/点数容量一起检查；冲突、画面缺失或归属不明时隐藏精确数字，等待下一局。
- 原字体/颜色悬浮条、超长扩展、金色竖条滑块、完整/仅计数独立尺寸、牌序拖动、按钮开关、双击隐藏、悬浮调整面板。
- 本机 SQLite 原子牌局快照，保留当前及最近 20 局；诊断 JSON 导出。可选 JPEG 诊断默认关闭、100 MiB 上限，无上传。
- 严格更新清单解析与 Ed25519 验签；每日检查、空闲 Wi-Fi 下载、断点续传、整包哈希、包名/版本/安装签名核验、系统安装确认。
- 持续安装签名和验签公钥已建立；私钥仅在忽略目录 `.signing`。参考原生库、字体、模型及脚本不进入 Git。

配置使用 SharedPreferences，牌局使用 SQLiteOpenHelper，这是原 DataStore/Room 计划的内部实现调整，交互不变。进程中断不假装恢复精确计数；快照供回看与诊断。

当前接入 full_fallback，输入 `[1,640,1280,3]`、输出 `[1,32,16800]`；标签为红/黑各 13 点数及两种王，不是精确四花色。

电脑 LiteRT 运行原 APK 自带标注图，31 个检测的点数多重集与 31 张标注一致；只证明该静态样本数量和点数分布，不证明每个坐标、花色或整局准确率。两张用户截图获得 28/14 个检测，遮挡、队友展示等仍需连续画面核对。

## 构建与服务验证

核心测试覆盖记账、颜色容量、观察状态、整组归属、签名和重复 JSON 字段拒绝。检查数和 APK hash 以最新构建为准。

更新服务 8 项单元测试通过。真实本地 Workers 静态运行时测试覆盖整包、跨分段 Range、后缀 Range、HEAD、禁止直接访问内部路径；发现无长度头和忽略 Range 的响应，已修复并按实际字节数校验。

专用 `jpq-release-store` 使用免费 Static Assets，仅有服务绑定，无 workers.dev 地址及其他项目路由，每片不超过 20 MiB。`jpq` 保留既有对外地址。未开通 R2/D1/付费存储或升级套餐，未发布未验收安装包。实测 `/health` 为 200、`/v1/releases/latest` 为 204。

## 真机发现与修复

- 手机型号 `2509FPN0BC`、Android 17 / API 37、澎湃 OS 4、arm64；主屏 1200×2608、480 dpi。游戏 `com.tencent.guandansy`，版本 3.2.1 / 300200101。
- USB 安装和输入操作曾被系统限制拦截；用户已在手机上开启相关设置，并明确授权自主测试，没有绕过系统权限检查。
- 首页已实际启动；开始按钮被内容挤出首屏，已固定在底部。
- 开始记牌失败：非显示服务 Context 不适合直接创建多屏悬浮 WindowContext。改为主屏 DisplayContext 后，真机确认 `local_recognizer_ready`、XNNPACK 初始化及 mediaProjection 前台服务运行。
- 第二次授权实际选中了副屏，系统记录 mirror display 1、尺寸 976×596；不能把该采集称为游戏识别成功。已改用官方默认主屏共享配置，正在复测。
- 悬浮 UI 保持用户可见，识别输入遮罩排除其自身数字。定位、方向、隐藏、完整牌局继续测试。
