## 证据与原因

录像正常收尾：3,244 帧、216.738 秒、最大帧间隔 270ms、无音频。只分析 ≤212 秒的游戏画面，退出游戏后的尾段不用于牌局标注。录制进行中读取到 0 字节不能证明录制失败，收尾后文件为 19,413,601 字节且可完整解码。

独立按视频牌面标注 38 次真实出牌，自己/上家/对家各出 27 张、下家出 22 张并剩 5 张；所有 108 张实体牌逐种各两张，初始自家 27 张与其实际出牌吻合。原图、视频、完整标注和大体积模型回放仅在忽略目录 `captures/phone`。

首个冲突发生于设备 elapsedRealtime `1471539196`。对家事件 `:8` 已从一张红 6 自动复核为 `666777`，共六张；上家 `4444` 出牌合法。录像约 76 秒的炸弹遮挡了仍留在桌面的旧 `666777`，模型 880–884 帧零检测被当成清空；恢复后重扣同组六张，导致红 7 累计 6 张、黑 6 累计 5 张而触发容量保护。不是上家四张 4 导致的问题。

同一开局的加倍 UI 反复出现/消失，使同一 27 张手牌无出牌时被初始化三次。终局约 203 秒下家展示的 `Q♥ Q♣ Q♠ 3♥ 3♦` 是末游剩余手牌，不能记为一次出牌。该局没有实际队友手牌视角。

## 修改

- 已有牌组的区域只有回到校准的桌面底色才允许清空。色度比值不受单纯亮度变化影响；白牌、金色炸弹和暗遮挡不能提供空区证据。覆盖该区域的悬浮窗也不能提供清空证据。
- ACTIVE、无事件、同一完整 27 张手牌的加倍 UI 变化保持原 roundId。
- 从真实位置识别自己的完成名次和末游展示。自己完成且两家外家各出 27 张后，保存 FINISHED 精确快照并等待下一局；不把最后五张亮牌扣掉，不补造自己的出牌事件。
- 原逐像素 RGBA 转换在实局约 72–100ms，改用复用 Bitmap 的 native bulk copy，处理行/像素填充。颜色、透明通道和实际采集耗时等待手机验证，尚不宣称速度收益。
- 诊断增加空区证据、置信度和完整框；剩余计数字段改为真正 JSON 对象。窄屏调整按钮保持可达，横屏保持原排布。

## 手机预检结果

- 六项 RGBA 测试首次有一项失败：`setHasAlpha(false)` 不会改原始 alpha，alpha=0 的红色仍返回透明像素。改为复用 IntArray、LE IntBuffer bulk transfer 和每个 word 的不透明高字节 OR。六项复测通过，包括 Canvas 颜色、行/像素填充与源缓冲状态。
- 实际炸弹遮挡图片通过 Android Bitmap 的空区证据检查。蓝色末游横幅被手机 OCR 完全漏读，未放宽为猜测文字；增加头游/二游/三游各对应唯一、不同完成座位的终局证据，横幅与徽章去重。原图及 1280×588 采集尺寸均通过实际 ML Kit OCR。八项图像检查总计 `OK (8 tests)`。
- 悬浮条遮住可能出牌区域时，首次未检到牌也不能当作空区，部分检测牌组不能当完整牌组；标定区域遮挡时延后学习桌布。持续遮挡走观察中断保护，不长期保留看似实时的旧统计。增加 16 项核心回归，当前核心共 97 项全部通过；lint 仍 0 错误、37 警告。
- 悬浮条采用屏幕范围和短边 cutout 布局。新日志实际测得该手机仍有12px顶部边距，默认遮罩为 `[0,0.01,0.4808,0.125]`；首版保守 ROI 的 `.12` 起点误判默认条遮挡，已改为与识牌中心 `>.13` 对齐，同时保留独立检测牌面框的相交保护。增加实测默认遮罩与部分牌面遮挡两个回归，核心总计99项通过。此前大厅预检已正常收尾，没有进入真实牌局，不算第二局验收。
- 本次 GPU 验证失败：无前台窗口的测试在 Bitmap Canvas 路径停滞；增加前台 Activity 的尝试则在测试框架 `startActivitySync` 等待超时。根因仍未确定，不能由此前一次成功推断可靠。清除该手机的 GPU 许可配置，当前使用 CPU；GPU 检查必须显式传 `-e validateGpu true`，且只在非对局阶段执行。
- CPU 原尺寸及缩放八张图复测通过手牌数量和座位检查；12 次检测中位 114ms、观测 P95 117ms。大厅另有 15 帧样本：转换中位 0ms/P95 1ms，预处理 2/3ms，推理 96/105ms，解码 1/1ms，帧间隔 102/109ms。静态本应用页面 251 帧转换 1/3ms。数字为阶段计时，0ms表示小于时钟毫秒分辨率；不代表整手延迟或达到参考软件速度。
- 主屏 0 共享实际启动，588×1280 与旋转后的 1280×588 均有帧证据；显示三家/重置关闭、双击隐藏配置开启后仍持续采集。电脑触摸未生效，键盘导航切换得到真实开关状态；此次双击手势本身不能记作通过。
- 签名开发测试工具 `DeviceEvidenceTest` 仅在显式 `exportEvidence=true` 时导出已停止采集的完整本机 ZIP；不属于准确性测试。显式 `resetTestDisplay=true` 才保存配置快照后恢复测试默认配置，启用本机诊断、禁用未通过的 GPU。已保存本机 ZIP 和恢复前/后 JSON，将上轮拖动留下的 y=0.011299435 恢复为默认 0。

## 复现入口

仅显式提供本机私有 tape 时执行，不纳入普通单元测试：

```powershell
./tools/android/build.ps1 -Tasks ':core:replayPhoneVideo','-PreplayTape=本机私有回放.tape','-PreplayOutput=本机结果.json'
```

tape 行为分号分隔的时间、场景、缩略像素尺寸、RGB24 zlib/base64、归一化牌面框、可见自身完成标记。其场景来源必须注明，不能把人工标记当成自动 OCR 成功。
