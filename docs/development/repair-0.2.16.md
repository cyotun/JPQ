# 0.2.16：真实级牌面板识别与提示方案边界

2026-10-15。候选 `0.2.16-regression` / code18；不作为稳定更新发布。

## 最近实局的事实

采用独立主屏 PNG 取证器后，r2 实局完整诊断 ZIP 共 501 项，CRC 校验通过。该局 29 次账本发布依次包含 ACTIVE、SELF_FINISHED、FINISHED、WAITING，没有 UNAVAILABLE；确认的是主流程连续到结算，不是每一手牌已独立证明准确。28 张低频主屏截图不能替代逐手真值，也未充分覆盖提前出完后继续观察队友的长阶段。

完整归档里有 102 条级牌记录：UNAVAILABLE 62、NOT_TABLE 31、HUD_CORNER_CONFLICT 8、HUD_ACTIVE 1；没有一次确认成功。同花顺旁路 390 条均为 NATURAL_ONLY，382 条曾读到物理 Q 角标，规则仍未确认。最后三家余量为 21/0/8，不能仅凭这个余量证明没有同花顺；本次没有验收变牌计算和暗灯。

实际提示目标曾测得正确的红色对方面板，且有一次确认被遮挡。但默认条高约 134px，屏高 1200px，上部安全边界 156px，12px 间距和 96px 提示无法同时容纳。现有安全几何返回空，所以用户看不到提醒。直接把提醒画到下方会侵入潜在出牌区；之前的真实故障证明不能简单忽略提醒遮挡。

## 已修复

真实清晰 Q 截图在旧 OCR 中丢失“我方／对方”标题，并把两枚 Q 合并。宽幅 2 倍 HUD 补图仍失败，失败结果保留。最终使用实际像素检测到的唯一双面板结构：头栏、紧邻白底、近等宽和共线均须成立。只有蓝灰、灰红、蓝红配色有效；灰色本身不宣告本局级牌。搜索框只限定工作量，不用于制造面板。

两个实际面板分别以 3 倍尺寸放在同一次 OCR 请求的独立补充行；原场景缩放不变。所有文字和真实字符边界映回原图；padding、跨图块元素、越出所属元素的字符均拒绝。标题可由实际“我／方”“对／方”字符框组成，10 仅由同一行唯一且不复用的 1/0 组成，不平均切分 QQ/JJ，也不替换模糊字符猜牌。

修复另一条恢复边界：先前 HUD／实际牌角冲突会建立更高证据门槛，后续完全一致的彩色 HUD 和物理角标仍可能一直无法恢复。现在只有完整彩色面板与实际角标的牌点集合精确一致，才可用三次独立新 OCR 时间、至少 500ms 的一致序列恢复；重复缓存、HUD 单独投票不能跨过该门槛。随机级牌公告的更高优先级、未知双级约束和灰色排除不变。
