## 第一局为何没有剔除队友牌

这不是六张 3 的大炸弹超出手牌容量。45318213 有一张旧对家顺子中正在移动的 SIX_RED 字框与顶部悬浮遮罩相交约 4px，遮挡判定有几何依据。与此同时，上家的新五张黑色 10/J/Q/K/A 已有两帧完整强读，但普通四票尚未提交。

原恢复只保存已提交的牌面，清掉这手未提交候选，把上家保存成“旧空区”。候选仍清晰存在时，恢复又要求这个位置一直为空；该旧空区时钟也已过 500ms。对家原五张回到原槽后，两个条件仍无法通过，导致本局约 97 秒恢复闭锁。后续真正显示队友手牌时，队友剔除因账本仍在恢复状态而无法启用。不能用后来的队友牌推断这 97 秒里的所有出牌。

新增 `LocalizedPendingPlayRecovery`，只保存中断前已有正面证据的候选：前一清晰空区后，候选两帧完整强读；遮挡必须发生在另一个有已提交完整几何锚的外座。候选在每帧仍须完整强读、同身份同实体槽，当前己手不变，其他未遮区持续原显示或正面为空。固定截止为最后一帧清晰中断前画面之后 1500ms，不能随返回牌面延长。遮挡座回到原完整身份、原槽后，再与候选共同完成两帧直接强读；有独立新鲜数量矛盾则拒绝。

通过时只把候选这一手作为新的 non-SELF 事件，通过账本的序号、座位最多 27 张和全局实体/颜色/点数容量检查后原子恢复。旧遮挡座的原牌不追加；旧空锚不伪造刷新。全局缺口、UNKNOWN、归属模糊、其他座新牌、己手变化、候选缺字/弱读/移动、超时或版本变化都会拒绝。真实严重遮挡仍不能制造未知牌。

新增 `QuantityAnchoredPlayProof`：仅处理已确认清空边界后的新牌，两次完整直接牌面、至少一次逐张强读、稳定几何；两个来源不同、相隔至少 100ms、在首个完整牌面之后且被读取时新鲜的同座数量读数。数量只佐证直接牌面张数，不能提供牌面身份。牌面收起后，最多在固定一秒候选窗口内等待连续正面空桌及数量读数；一旦新牌、盲区、矛盾数量、倒序/未来来源、版本/场景改变即清除。重复缓存不增加数量票，变旧的缓存弃权，不清除仍在固定短窗口内的已有正面证据。

同一末局另有一对 SIX_BLACK 只留下三帧完整显示，旧版也未记下。两个独立数量 2 的来源与新的剩余张数吻合，现一并记录。正确的终点是前家和下家各出完 27 张；匹配源图显示二游/三游及队友仍剩 Q 一张。旧版漏了七张后，反而把后续队友剩牌展示算成最后出牌。修复后在正确结束点停止，不记入那张结算剩牌。

## 用户另问的参考 APK 采集

原 APK 的普通与 GPU 链路都使用 MediaProjection，原始 DEX 确认其名为 `applyFloatingWindowMask` 的方法并不修改 Bitmap；实际黑块来自玩法配置的 BlockAreaMasker。未找到排除悬浮层、逐帧隐藏或采到下层完整游戏原图的机制。按用户条件，不增加无正面证据支持的采集方案改动。静态审计不是同设备运行对照，native/OEM 的未证实部分仍明确保留；详见 `docs/research/reference-capture-occlusion-review.md`。
