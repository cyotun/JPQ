# 记牌器BETA C4.9：停记路径的系统复核

## 结论与范围

C4.8 已修复上一轮四局的具体识别与交接问题，但其代码仍保留“一家待确认导致整局等待”的共同失效方式。用户要求再次 review 并举一反三，本轮据此增加故障复现、修改状态处理并完成电脑检查；没有操作手机、没有开始实战，也没有发布正式更新。

本轮使用 Luna 并行检查输入链、恢复状态和测试，使用 GPT-6.1-Sol 实现单家证明。所有实现、测试预期和后续修正由主代理复核。未使用 Astra 子代理。

## 为什么具体问题修复后仍可能停记

过去把几类性质不同的情况汇入全局 `incomplete()`：单家牌组到底是旧展示扩展还是新出牌；一个被容量校验拒绝、实际没有写入的错误识别；真正的画面缺失。进入全局检查点后，其他家也不能提交，恢复可能依赖过时牌面重新出现或多家余牌提示同时满足。在牌局继续推进后，这些条件可能一直不再出现。

这是 review 发现的结构风险，不是声称每次历史漏记都只有同一个原因。原 C4.7 实战中的已证实问题及 C4.8 针对性修复仍见上一版报告。

## 本轮修复

- **单家待确认隔离**：无物理关联的严格超集不再直接挂起整局。保留其原事件及完整直接牌组证书，其他家和本家有独立证据时继续记账。该家的多个直接牌组与独立余牌数量只能在唯一解释成立时一次性写入，不猜牌，不跳过早先未确认的一手。
- **错误提案隔离**：容量或身份校验拒绝的追加和扩展没有改变账本，现只丢弃该次提案、重新投票；同一帧的其他家也继续处理。增加拒绝数量诊断。
- **普通噪声可恢复**：单次低分、残缺和数量 OCR 错误只清除相应临时票数，不永久锁死单家证明。返回后须重新取得四次完整位置读取及三个更新的数量来源。缓存、未来时间、同来源冲突均不提供票数。
- **中断边界一致**：短归属歧义即使提前返回，也会暂停单家取证；不能把歧义前后数量票拼起来。独立定位的局部遮挡不硬性封锁无关 journal；局部检查点不再要求已由 journal 管理的家显示过时牌面。真实采集缺口继续保持保守约束。
- **提交及结束约束**：单家事务验证成功才消费证明；被拒绝的事务仍可保留。终局证明不在无法提交时被提前消费。结束时仍有待确认单家记录，会明确留下未核实结果，不能把“界面没有停掉”误判为整局正确。
- **去掉同帧重复中断**：归属歧义分支已处理该帧的不完整原因时，不再紧接着调用第二次中断；持续歧义使用当前时间推进边界。

具体设计和以后修改时必须检查的约束见 [识别、记账和恢复的约束](recognition-recovery-invariants.md)。`ObserverStatus` 及手机轨迹新增 `pendingReviewSeats`、`rejectedPlayCandidates`，方便区分单家暂缓、全局缺口和识别拒绝。

## 电脑验证

- 核心 **848 项**，比 C4.8 新增 28 项，零失败、零跳过。
- BETA 宿主 **26 项**、正式配置宿主 **26 项**通过；正式配置仅运行宿主测试，未制作或发布正式安装包。
- 来源工具 **41 项**、证据清理工具 **10 项**通过。
- BETA APK、测试 APK 构建和签名核验通过；lint 零错误、59 条既有警告。
- 完整重跑保留的三个连续会话：**16 局、23319 帧、564 个事件**，无未解决终局、无全局恢复停滞。每段会话从头连续执行，未按局重置或剔除正常局。
- 逐局比较 C4.8 的最终事件身份、座位、序号和牌的多重集合，全部一致；队友牌池历史完全一致。不是只看回放进程正常结束。

新的故障检查包括：一家等待时另外两家及自己继续出牌、独立数量来源恢复、临时弱读恢复、单次错误数量恢复、缓存来源不增票、短歧义后的重新取证、另一家的局部遮挡与待确认组合、容量拒绝及扩展拒绝、原子事务失败后重试、终局未核实及跨局清理。

这些是保留模型／场景／原始 OCR 来源的连续回归和构造故障检查，并非逐张独立人工真值，也不是本版新的手机或实战验收。不能据此宣称所有对局均准确或 99.9% 无异常。
