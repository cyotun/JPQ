# 0.2.15 非对局手机检查

2026-10-15。用户连接并解锁后，保留数据升级到 0.2.15-regression / code17。未进入或自动操作游戏；真实整局另行验收。

## 发现与修复

手机上原首页完整可见，开始/停止、设置返回和更新入口可用。新增的实际截图补测发现：左上角两个队伍的 J 被 MLKit 合并为 `JJ`，队伍标签还可能成为 `|我方对方`。这与出牌记录中的一对 J 无关；旧过滤仅接受单字，导致本局级牌未确认。

复用现有异步 OCR 返回的真实字符坐标，保留每个 J 所属位置；只去除精确队伍标签两边的分隔线。`10` 用相邻的真实 1/0 字符范围合并，不按词框等分、不把单个 1 或 0 当级牌，不增加 OCR 请求或阻塞牌面检测。蓝色 J 的实际截图和原级牌 3 截图均复测通过。

另一个用户截图的 HUD 数字被系统状态图标覆盖。最初试验把它标成应当读出 Q，实际看图后纠正了测试前提：只靠该处遮住的 HUD 无法确定 Q，应保持未知；没有用灰色进度或其他界面数字填补。画面中队友金心 Q 是另一个物理牌角来源，需要独立满足其识别规则。

同花顺配色检查首次失败是测试仍在旧固定宽度坐标取样，实际取到了其他牌格。将取样点改为实际窗口中图案槽位中心后，未知/可能为金色、排除为灰色及开关宽度均通过；未因此修改生产配色。停止/启动位置测试也改为保留实际字体测得的牌格宽度。

初始失败输出和截图仍保存在本机忽略目录，没有将其计为通过。最终 APK 已重新安装，哈希见[实现记录](repair-0.2.15.md)。

## 实际采集与横竖屏

使用独立测试 APK 的色块/计数器画面，没有打开游戏。确认 MediaProjection 为 display0 整屏采集、非单应用任务投影。三帧原始 RGBA 与转换后位图比较，RGB 不同像素数和最大通道差均为 0。

此处是合成动态画面，未复现此前偶发的实局采集沉默，不能据此宣布所有沉默已修复。该画面走完整检测，推理中位数 103ms、P95 109ms；不能作为真实牌桌打包管线的速度结果。
