# 记牌器BETA 与正式版发布流程

2026-10-24，按用户最新决定执行。项目级约束见根目录 [AGENTS.md](../../AGENTS.md)。

| 项目 | 记牌器BETA | 记牌器（正式版） |
| --- | --- | --- |
| 包名 | `com.cyotun.jpq.candidate`，沿用已有测试数据 | `com.cyotun.jpq` |
| 用途 | 新功能、识别修复、性能优化的开发和验收 | 已验收功能的日常使用 |
| 更新 | 当前不读取或安装正式通道 | `jpq` 的签名正式清单和安装包 |
| 安装关系 | 可与正式版共存 | 不能被 BETA 包覆盖 |

“candidate”仅是历史包名、Gradle 构建类型和源码开关，不代表用户可见名称。旧证据文件名不改写。

## 开发到验收

1. 从现有正式标签保留回滚 APK、哈希、证书和源码，再在开发分支制作 BETA。
2. 主代理复核全部改动，先运行核心测试、应用宿主测试、静态检查与相关电脑模拟测试。记录失败和修复，不能把跳过算作通过。
3. 无需对局的真机采集、界面和启停检查通过后，再由用户正常完成真实牌局；期间只读取证据。保存本次包哈希、采集范围、会话和逐手核对结果。
4. 达到本轮验收条件后，确认哪些功能可以进入正式版本。缺少原始证据或尚未实战通过的改动继续留在 BETA。

## 提升到正式版本

不要直接把包含其他未验收改动的 BETA 开发分支构建为正式 APK。必要时从上一个正式标签创建 `codex/` 发布分支，只合入已验收改动，复跑相关完整回归。

正式版保持包名、安装证书和数据结构兼容，`versionCode` 严格增加。构建后核对真实 APK 包名、版本、minSdk、证书和 SHA-256。使用 `tools/release/package.mjs` 生成 Ed25519 签名清单和不可变分片；此脚本会拒绝 BETA 包名。

先在本地验证服务和分片下载，再部署专用 `jpq-release-store`。通过 `jpq` 的生产入口验证签名清单、HEAD、跨片 Range、整包哈希和安装身份后，更新发布文档和源码标签。服务仅用于更新，不上传私人对局资料。

正式 APP 每日自动检查、空闲时在 Wi-Fi 下载；用户也可在「设置 → 应用更新」手动操作。安装仍使用 Android 系统确认，对局期间不下载或发起安装。

## 回滚

每版保留上一正式 APK、源码标签、签名身份和部署版本。BETA 失败时停止 BETA 共享后使用仍共存的正式 APP；不卸载或清空正式数据。已发布正式版的代码回退使用更高 `versionCode`，不让 Android 自动降级。

当前正式基线仍为 `v0.2.26` / versionCode 28。2026-10-24 首次恢复该原始 APK 的服务器分发，未将本轮 BETA 识别改动提升到正式通道，见 [更新服务验证](official-updates-20261024.md)。
