# 真机对局测试计划

2026-10-12。用户确认游戏没有人机对局，必须由用户进入真实牌局并正常玩完。

## 操作边界

对局开始前完成安装、授权、显示设置、日志与录像启动、计时校准。由用户选择并进入对局。对局期间助手只读取记牌器日志和已授权的游戏画面，不点击游戏、不打开设置、不安装版本、不停止记牌或中断牌局。全部变更、导出和下一轮配置只在用户回到大厅或确认本局结束后执行。

多 agent 分工时，只有主代理操作同一台手机。其他代理只检查代码、离线样本或已收集的本地证据，避免同时安装、授权或占用录屏。任何采集故障都只停止采集器自身，不通过重启游戏或记牌服务掩盖本局失败。

## 先完成的无需对局检查

1. 用用户四张失败截图及参考截图回放牌面检测、叠牌归属、自己/三家区域和初始 27 张。
2. 自动测试短时动画、同牌再次出、短时未观察区域、设置变化、新局恢复、贡牌和队友展示，禁止以猜补数量通过。
3. 在手机上用固定图像比较 CPU/GPU 输出与耗时，记录采集转换、预处理、推理、归属、OCR、确认、渲染的独立耗时。性能改动先核对识别结果。
4. 在大厅检查开始/停止、横屏、隐藏/恢复、双击、按钮开关、三家开关、尺寸/牌序、配置持久化。显示调整不得直接清空或重建账本。

## 对局日志与证据

每次测试有独立 session ID、版本号/提交号、模型 hash、手机/系统/游戏版本、源尺寸/采集尺寸/密度、显示配置。结构化记录按单调时钟保存：帧号、场景、候选牌组及座位、确认票、事件号、计数、初始化/恢复/冲突原因、各阶段耗时。原始截图或录像仅保存到本机私有目录，不上传 Git 或 Cloudflare。

主代理使用 `tools/android/collect-live-test.ps1` 采集。脚本要求 PowerShell 7，固定使用本地校验过的 scrcpy 5.0.1，选择唯一连接设备或明确指定 `-DeviceSerial`。不读剪贴板、不录音、不弹镜像窗口、不注入输入、不唤醒手机；1920 长边、15 FPS、3 Mbps MKV 只是证据录制参数，不是记牌模型输入分辨率。先在非对局画面检查编码器启动、MKV 可解码、停止后能写完尾部；这项自检不能替代完整牌局。

采集器仅在唯一前台 resumed 应用为大掼蛋、全局 named wakefulness 为 Awake、Keyguard showing=false 时启动录像；未知、锁屏、熄屏或切出游戏均停止录像。HyperOS 双屏的 numeric wakefulness 和多个 ScreenOn 字段不能作为任一显示为 true 即开始的条件。原始 dumpsys 内容和非游戏应用名不保存。守卫轮询默认 500 ms，ADB 每次读取有 2 秒超时；查询、编码缓冲与正常收尾均有延迟，因此并非应用级隔离录屏。切屏/锁屏段落标记 `reviewTail=true`，先剔除非游戏尾帧后再查看、标注或导出；尾部边界不明时不使用该片段来证明事件正确。

主机仅收集 `JPQCapture/JPQRound/JPQVision/JPQTrace` 标签，不清空 logcat，不收集不限包名的 AndroidRuntime。`JPQTrace` 紧凑 JSON 供对局中观察，完整私有 JSONL 在结束后由 APP 的 SAF ZIP 导出。优先在开启记牌前启动采集器，以保留新的 session 元数据；若仅拿到截断的 logcat，必须使用完整导出补齐。主机元数据的 APK hash 仅对应本地构建文件，不等于证明手机安装了同一文件；已安装版本由 session 记录及安装回执确认。

`markers.jsonl` 保存采集开关、守卫布尔值、异常和每分钟时钟校准。每次 `/proc/uptime` 读取前后记录主机 UTC，用往返时间一半加 10 ms 量化余量表示校准不确定度。设备 uptime 可与 APP 的 elapsedRealtime 关联，但 MKV 的零点是首个编码帧，不能直接等同 scrcpy 进程启动时刻。逐帧延迟核算需先找两份证据共同可见的事件校准偏移，并保留录制 15 FPS 的帧间隔误差。

正常结束后，在该次 `captures/phone/live-…/` 内创建 `stop.signal`。采集器只对自己创建的隐藏独立控制台发送 Ctrl+C，让 scrcpy 正常关闭 recorder 并写完容器；信号或退出超时才终止自己的子进程，并记录 `forced=true`。不杀 ADB server、不杀游戏、不操作记牌的 MediaProjection。退出码、文件大小与 MKV 可解码仍需核对；有强制退出、录像缺口、日志缺口或缺失首手证据的牌局不能通过整局验收。

无需手机即可运行 `tools/android/test-live-test-support.ps1`：检查前台/锁屏解析、未知状态拒绝、读命令超时、大量双管道输出与独立控制台正常收尾。`tools/android/analyze-live-trace.py` 汇总本地 JSONL/logcat 的阶段耗时、场景、不可用原因和已确认事件；它明确不判定记牌正确，也不把同一事件在后续账本快照里再出现视为重复出牌。原始视频人工标注仍是准确性证据。

先跑一局定位，再做回归局。每次均从大厅或新局发牌前启动记录，到用户完成整局并确认结束才收尾。出现错误继续保留证据，用户正常打完，不为调试中途重启。完整对局逐事件与画面人工标注比对；漏记、错记、重复记、无依据的精确显示或异常停记均记为失败，不能仅检查最后总数。

人工标注先只看游戏牌面，记录「视频片段/PTS、整局 ID、序号、座位、实际牌组、稳定起始帧、可见遮挡/动画」，再与识别事件匹配；避免按记牌器结果反推实际牌组。自己初始 27 张独立逐张核对。每一手另外记录确认事件 elapsedMs、首次正确渲染 PTS 和延迟区间。没看清的帧标为证据不足，不能猜补成通过。检查未出牌/重复牌、自己出完后的视角，以及整个牌局结束到下一次有效发牌的恢复过程。

## 回归组合

| 对局前配置/场景 | 检查内容 |
| --- | --- |
| 默认显示 | 27 张初始化、首手、连续三家、自己出牌不重复扣除 |
| 隐藏重置/三家、双击隐藏 | 内部事件与默认配置一致，恢复时显示当前真实状态 |
| 调整尺寸/牌序后重开 | 配置正确，下一局自动初始化，不继承不可用状态 |
| 重复牌组、顺子、炸弹 | 每次有效出牌只记录一次，不把动画/叠手牌计作出牌 |
| 贡还牌、自己出完与队友手牌 | 阶段和基线正确，不错误新局或二次扣牌 |

初始化和事件延迟以画面中的完整牌面稳定时刻为起点，分别报告中位数与 P95，不把发牌动画、网络等待或人为操作算成模型耗时。与原 APK 比较时使用相同录制画面与事件标注；没有数据前不声称已达到参考速度或准确率。

只有离线回归和完整真机对局通过后，才发布稳定版本并进行应用更新安装验收。第二部手机与长时间后台运行单独记录，不能由第一部结果代替。

当前状态：已准备上述采集与离线校验路径；尚无经独立逐事件标注通过的完整真机牌局。因此不记录「稳定记牌通过」或「达到参考 APK 水平」。后续测试结果在对应版本记录中填写，不把工具自检结果写成对局验收。

收尾方法依据 scrcpy 5.0.1 的 [Windows Ctrl+C 处理源码](https://github.com/Genymobile/scrcpy/blob/v5.0.1/app/src/scrcpy.c)：控制事件进入 SDL quit，允许 recorder 正常收尾。具体手机编码器的退出行为仍以本地试录和文件可解码验证为准。
