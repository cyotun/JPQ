# 真机对局测试计划

2026-10-15 更新取证方法。用户确认游戏没有人机对局，必须由用户进入真实牌局并正常玩完。

## 操作边界

对局开始前完成安装、授权、显示设置、日志与录像启动、计时校准。由用户选择并进入对局。对局期间助手只读取记牌器日志和已授权的游戏画面，不点击游戏、不打开设置、不安装版本、不停止记牌或中断牌局。全部变更、导出和下一轮配置只在用户回到大厅或确认本局结束后执行。

多 agent 分工时，只有主代理操作同一台手机。其他代理只检查代码、离线样本或已收集的本地证据，避免同时安装、授权或占用录屏。任何采集故障都只停止采集器自身，不通过重启游戏或记牌服务掩盖本局失败。

## 先完成的无需对局检查

1. 用用户四张失败截图及参考截图回放牌面检测、叠牌归属、自己/三家区域和初始 27 张。
2. 自动测试短时动画、同牌再次出、短时未观察区域、设置变化、新局恢复、贡牌和队友展示，禁止以猜补数量通过。
3. 在手机上用固定图像比较 CPU/GPU 输出与耗时，记录采集转换、预处理、推理、归属、OCR、确认、渲染的独立耗时。性能改动先核对识别结果。
4. 在大厅检查开始/停止、横屏、隐藏/恢复、双击、按钮开关、三家开关、尺寸/牌序、配置持久化。显示调整不得直接清空或重建账本。

## 对局日志与证据

每次测试有独立 session ID、版本号/提交号、模型 hash、手机/系统/游戏版本、源尺寸/采集尺寸/密度、显示配置。结构化记录按单调时钟保存：帧号、场景、候选牌组及座位、确认票、事件号、计数、初始化/恢复/冲突原因、各阶段耗时。原始截图或录像仅保存到本机私有目录，不上传 Git 或 Cloudflare。

主代理使用 `tools/android/collect-live-test.ps1`，选择唯一连接设备或明确指定 `-DeviceSerial`。默认使用单次 `screencap` 主屏 PNG 序列；不启动 scrcpy、screenrecord 或第二个镜像虚拟显示。`-LogsOnly` 可禁用截图。`-SyntheticProbe` 仅接受专用测试 Activity，不能录制真实游戏。

0.2.15 本轮在双屏手机复现了第二路镜像录像退出后，记牌器自己的 MediaProjection 仍显示有效、但持续没有新帧的问题；详见[本轮失败定位](live-round-failure-0.2.15.md)。禁止在真实测试中重新使用旧 scrcpy 采集路径。不要为规避测试冲突而擅自放宽记牌账本校验。

主屏通过 SurfaceFlinger 的 `HWC display 0` 对应物理编号确定，缺失或歧义则拒绝截图，不默认抓取背屏。前台守卫仅分析 Activity 列表的 Display #0，背屏 resumed Activity 不授权或否决主屏。主屏须唯一前台大掼蛋、全局 named wakefulness 为 Awake、Keyguard showing=false。截图前后各检查一次；未知、锁屏或切换的样本直接丢弃，不保存无关应用名和原始 dumpsys。采集范围仍有有限时间边界，查看前保留隐私复核要求。

PNG 保留原尺寸，不修改模型输入。最低请求间隔 1000ms；截图与双重守卫有开销，实际频率更低，以 `frames.jsonl` 每帧起止 UTC 为准，不能称为 15 FPS 录像。仅保存完整 PNG，512MiB 后停止加图、继续保存日志。主机输出不读剪贴板、不录音、不注入输入、不唤醒手机。开始和停止取证均需先用动态非对局画面证明不影响 APP 的新帧消费。

主机仅收集 `JPQCapture/JPQRound/JPQVision/JPQTrace` 标签，不清空 logcat，不收集不限包名的 AndroidRuntime。`JPQTrace` 紧凑 JSON 供对局中观察，完整私有 JSONL 在结束后由 APP 的 SAF ZIP 导出。优先在开启记牌前启动采集器，以保留新的 session 元数据；若仅拿到截断的 logcat，必须使用完整导出补齐。主机元数据的 APK hash 仅对应本地构建文件，不等于证明手机安装了同一文件；已安装版本由 session 记录及安装回执确认。

`markers.jsonl` 保存守卫布尔值、异常、收尾与每分钟时钟校准。每次 `/proc/uptime` 读取前后记录主机 UTC，用往返时间一半加 10 ms 表示校准不确定度。`frames.jsonl` 保存每张图捕获前后时间和接收时间，关联 APP elapsedRealtime 时须包含截图和时钟不确定度。低频图片无法精确测量逐手低延迟，也不能凭日志补造没拍到的牌面真值。

用户确认整局结束后，在本次 `captures/phone/live-…/` 创建 `stop.signal`。只关闭采集器自己拥有的 ADB 日志子进程，不杀 ADB server、不杀游戏、不操作记牌器的 MediaProjection；每次截图是自行结束的单次读取。导出完整 APP ZIP，校验 ZIP 完整性和新 session 元数据。日志缺口、画面漏拍或未取得初始手牌的测试不能按逐手准确率通过；证据不足需明确标出。

无需手机即可运行 `tools/android/test-live-test-support.ps1`：检查前台/锁屏解析、未知状态拒绝、读命令超时、大量双管道输出与独立控制台正常收尾。`tools/android/analyze-live-trace.py` 汇总本地 JSONL/logcat 的阶段耗时、场景、不可用原因和已确认事件；它明确不判定记牌正确，也不把同一事件在后续账本快照里再出现视为重复出牌。独立画面人工标注仍是准确性证据；未拍到的事件不能由程序结果反推。

先跑一局定位，再做回归局。每次均从大厅或新局发牌前启动记录，到用户完成整局并确认结束才收尾。出现错误继续保留证据，用户正常打完，不为调试中途重启。完整对局逐事件与画面人工标注比对；漏记、错记、重复记、无依据的精确显示或异常停记均记为失败，不能仅检查最后总数。

人工标注先只看游戏牌面，记录「图像文件/捕获时间区间（或经独立验证不干扰采集的视频 PTS）、整局 ID、序号、座位、实际牌组、稳定起始帧、可见遮挡/动画」，再与识别事件匹配；避免按记牌器结果反推实际牌组。自己初始 27 张独立逐张核对。每一手另外记录确认事件 elapsedMs、首次正确显示的画面时间区间 和延迟区间。没看清的帧标为证据不足，不能猜补成通过。检查未出牌/重复牌、自己出完后的视角，以及整个牌局结束到下一次有效发牌的恢复过程。

## 回归组合

| 对局前配置/场景 | 检查内容 |
| --- | --- |
| 默认显示 | 27 张初始化、首手、连续三家、自己出牌不重复扣除 |
| 隐藏重置/三家、双击隐藏 | 内部事件与默认配置一致，恢复时显示当前真实状态 |
| 调整尺寸/牌序后重开 | 配置正确，下一局自动初始化，不继承不可用状态 |
| 重复牌组、顺子、炸弹 | 每次有效出牌只记录一次，不把动画/叠手牌计作出牌 |
| 贡还牌、自己出完与队友手牌 | 阶段和基线正确，不错误新局或二次扣牌 |

初始化和事件延迟以画面中的完整牌面稳定时刻为起点，分别报告中位数与 P95，不把发牌动画、网络等待或人为操作算成模型耗时。与原 APK 比较时使用相同录制画面与事件标注；没有数据前不声称已达到参考速度或准确率。

只有离线回归和完整真机对局通过后，才发布稳定版本并进行应用更新安装验收。第二部手机与长时间后台运行单独记录，不能由第一部结果代替。

当前状态：已准备上述采集与离线校验路径；尚无经独立逐事件标注通过的完整真机牌局。因此不记录「稳定记牌通过」或「达到参考 APK 水平」。后续测试结果在对应版本记录中填写，不把工具自检结果写成对局验收。
