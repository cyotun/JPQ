# 记牌器BETA C4.5：过牌后严格超集的确认

## 本轮发现

C4.4 的五局实战记录中，第二局下家累计出牌停在 3 张。日志显示这不是单独的数字控件失刷：第 16 个事件后，队友的新五张牌包含早先单张 2 的同点数、同颜色读数，进入旧牌面扩展冲突；全局账本随后停在复核状态，直到结算。截图和简要日志支持这一触发路径，早段逐张位置与独立余牌数量来源已被旧轮转策略覆盖，不能声称已完整逐帧复现该局。

四张本轮原始截图经手机实际 OCR 和 FULL/CPU 模型重读后，进一步确认：游戏描边的「不出」会被识别为精确字串「不础」。原始空区检查仍可能把过牌文字视作前景，不能仅凭「没有检测到牌」清除旧展示。

其余四局检查了最终事件序列、各家张数、四处同事件补齐和关键收尾/队友视角画面。三处有同会话诊断原图支持，早段一处只有物理截图时间窗；这不是全部事件逐张独立标注。五局确认级牌无变更；1142 条同花顺分析记录中，显示候选集合没有回亮，两个原始集合短暂扩展均被显示缓存拦住。未将这些抽查结果扩大为全局准确性承诺。

## 实现边界

- `TencentPass.kt` 只接受有尺寸、位置约束的三家过牌气泡，精确识别「不出／不要／不础」。中央自己的不出按钮、昵称、缺位置或错误尺寸文字不参与。
- `TencentFrameVisibility.observedPasses` 绑定 OCR 原始采集时间、尺寸、可见性代次，来源和当前遮挡集合都须合格，当前座位无牌检测。超过一秒、未来时间或队友视角不生成此证据。
- `PassClosedSupersetProof` 保留旧事件和物理锚点。必须已确认其他座位的后续出牌、取得两个独立新过牌来源，再观察到完整的、物理位置变化的严格超集。新组需要四个强且位置稳定的读数；同牌仍占旧槽位时不能通过。过牌本身不等于像素空区，也不产生牌或修改张数。
- 原手必须与当前账本一致，阶段仅 ACTIVE/TABLE。遮挡、场景切换、时间不连续、旧牌返回或版本变化使证明失效。没有合格过牌证据时继续使用原有严格超集检查与独立数量证明，不能猜牌。
- 通过后使用普通原子提交新增整手，旧单张不变；出牌数量和余牌从同一账本更新。回放文件新增可选过牌来源列，旧 `passing` 字段不获得合成来源。
- 本机诊断由两个 8 MiB 文件改为最多七个文件，约 56 MiB。保留原导出目录和总清理配额，避免几局后早段详细证据过早丢失；仍不上服务器。

## 电脑验证

核心 697 项、BETA/正式配置的宿主检查各 26 项通过；BETA lint 为 0 错误，59 条既有警告。回放准备和来源校验工具 32 项通过。

新增场景回归验证：旧单张 2、其他座位出牌、过牌、随后包含另一张 2 的五张新组能正常新增，之后下家仍继续记账。缓存过牌、反向/过期来源、同槽旧牌及其颜色闪变、遮挡、错误手牌和没有合格过牌等反例不放宽。

两组已有连续素材共 8865 帧的事件历史和队友牌池投影与修改前逐项一致。当前五局素材的 3717 条帧记录仅有一局具备完整基线及连续证据：该局 41 个事件、四家 27/19/27/27，与手机记录一致，未出现复核卡住；其余不能算作完整通过。旧素材不会补造新加入的过牌来源，因此不能据此宣称第二局修复已完成实战验收。

## 手机验证与交付

本轮仅做非对局验证，没有进入游戏对局。详细范围、安装包哈希、还原与收尾状态见 `single-app-candidate.json` 的 `betaC45`。

最终包的 90 项手机检查通过：过牌来源/遮挡/存储 24 项、其他组件与模型 50 项、首页和隔离 8 项、悬浮交互 7 项、实际单应用采集 1 项。四张本轮原图的合格过牌座位均与逐图核对相符。实际采集的 119 条完整牌面读数一致；三个原始 Image 与模型探针配对，转换及遮挡副本像素差为 0。

另以正常首页流程验证开始、系统单应用授权、停止记牌：未在采集中执行 instrumentation，正常停止后投影为 null 且 CaptureService 消失。之后才进行最终清理，恢复显示配置、诊断开关和原辅助包，USB 设置保持原值。BETA 最终安装包哈希与本地交付产物一致，正式 APK/版本/更新时间不变；测试程序关闭，手机回到桌面。

C4.5 仍为独立「记牌器BETA」。正式版、服务器更新清单及回滚包保持不变。状态为电脑与手机非对局检查通过、实战验收待用户安排，不提升正式版。
