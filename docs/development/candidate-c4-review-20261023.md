# C4 复查修复记录

2026-10-23，基于候选提交 `2a28e58`。本轮按用户要求重复复查、修复并重新验证，只使用电脑和 Android 模拟器，不连接或操作手机。原 C4 构建和稳定 v0.2.26 回滚材料单独保留。

## 复查发现与修复

### 后台写入者关闭异常

写入异常虽然会被记录，但 `finished` 中关闭文件或数据库失败仍可能跑出后台线程；正常退出分支的完成信号也未可靠到达。故障注入测试先复现失败，再将收尾放入独立的 `finishSafely` 方法：关闭异常走统一的失败回调，完成信号在 finally 中释放，失败回调自身抛错也不会阻断收尾。

`SessionTrace` 的缺口记录和流关闭改为嵌套 finally，确保缺口写入失败时仍尝试关闭流并释放 writer lease。测试同时注入写入失败、关闭失败，检查后台线程没有未捕获异常、两项错误均被报告、关闭等待正常结束。

### 普通诊断导出没有等待后台记录

ZIP 已等待写入排空，但普通 JSON 导出仍在主线程直接读库，可能遗漏刚停止时尚未保存的末尾快照。现将 JSON 和 ZIP 统一到后台导出入口，在维护锁内等记录写完并读取快照，再打开用户选择的目标文件。

录屏正在运行或维护检查不通过时，目标文件不会被打开和截断。导出资源由一个确定的调用方关闭，避免重复关闭会报错的文档提供器被误判为导出失败。两种导出都保留停止记牌后操作的约束，不改变游戏中的记账逻辑。

### 数据库拒绝插入被当成成功

Android SQLite 的插入 API 可能通过 `-1` 返回失败，而不是抛异常。现在牌局快照和花色旁路证据均检查返回值。失败的牌局保存不提交事务、不继续裁剪历史记录，并由后台保存层记录错误；花色证据保存失败也不标记为已持久化。

模拟器测试通过数据库触发器真实拒绝两种插入，确认调用报告失败，原有牌局状态和花色证据保持不变。

继续沿失败调用链发现，花色证据保存异常原先会进入同花顺分析的总异常处理，可能把已经接受的显示重置为未知。现隔离持久化失败：仅记录诊断错误，不改变已算好的同花顺、候选点数和级牌数量；失败后不标记已保存，存储恢复时可用相同证据重试。新增真实 SQLite 拒绝写入后恢复的检查。

### 日志轮换失败后的重新打开

轮换失败可能留下当前文件，而原来的重新打开方式会截断该文件。现在先撤销旧流引用，再关闭；重新打开使用追加模式，保留此前已经写好的日志。测试在轮换目标位置放置不可替换的非空目录，确认前后两份标记均仍在当前文件，writer lease 正常释放。

## 反复复查范围

修复后重新检查调用方与资源所有权，补上导出目的流只关闭一次的回归；随后分别复查以下边界：

- 开始/停止与导出、清理、自动保留量维护的互斥；父 writer lease 覆盖延迟创建的子写入者。
- 队列容量、同局完整快照替换、关闭排空、写入和关闭失败；不从后台读取活动账本。
- 更新安装的文件锁、不可变副本、主线程交接超时、Activity 销毁、重新开始记牌、候选禁止稳定更新。
- 原始 RGBA 的字节顺序、行填充、裁剪补边、透明度、目标缓冲复用，以及普通帧/手动探针的单等待位置。
- JSON 与 ZIP 的停止条件、读取时机、目标文件打开时机、异常关闭和 Activity 生命周期。

最后两轮静态复查未再发现有证据支持、需要修复的明确问题。这不代表能证明所有设备、所有真实对局或所有存储故障下零异常；真机采集、整局和耗电/温升仍单独验收。
