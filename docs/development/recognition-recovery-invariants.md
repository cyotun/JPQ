# 识别、记账和恢复的约束

适用于记牌器BETA 的开发和 review。正式版只能提升已经完成电脑、必要真机及用户实战验收的改动。

## 区分三种失败

1. **观测提案不合法**：容量、事件身份或手牌差分校验未通过，且事务没有写入账本。拒绝这次提案、重新取证；不能仅因此把有效账本变为全局恢复。其他座位仍应获得处理机会。记录 `rejectedPlayCandidates` 便于审计。
2. **单家展示有歧义**：例如已确认的一张牌消失，后来出现包含同点数的完整新牌组，但没有原物理槽位关联。保持原事件，使用单家 journal，独立处理其他座位及本家手牌。不能仅凭点数包含关系，选择“扩展旧手”或“新增一手”。记录 `pendingReviewSeats`。
3. **真实采集或全桌连续性缺口**：可能确实有看不到的出牌。保留不可变检查点，只接受有独立证据的恢复；不能用后来的任意合法牌组跨过未知历史。此时禁止用已有单家 journal 冒充无缺口的证据。

## 证据生命周期

- 原牌组、事件身份、所属局和已确认历史不可变。只有严格追加的其他座位事件可以与单家待确认并行；改写、跨局或真实采集缺口必须阻断旧证明。
- 临时票数、已经取得的完整牌组证书和固定截止时间分别管理。普通弱读、残缺、数量 OCR 噪声不能永久毒化整个证明；但它们也不能投票、延长有效期或补出未看清的牌。
- 场景提前返回前也要通知待确认记录。短动画之后须重新取得完整几何证据，不能偷偷连接前后两组票数。
- 数量来源使用原采集时间。同一来源重复送达不增加票数，同一来源互相矛盾要废弃其票数。不得用送达时间刷新旧 OCR。
- 级牌及已确认数字的显示保持本局确认值；取证在后台进行。稳定显示不代表已经证明所有待确认出牌，应在诊断中保留真实待确认状态。

## 单家严格超集的有限恢复

`UntrackedSeatReview` 只保存直接观测到的牌，不写账本。完整牌组须具有一一对应、互不重叠的有效位置及颜色身份，至少四次强读取、跨度至少 180ms。普通弱读后必须重新取得完整行，再收集数量来源。

数量确认至少需要三个不同的新来源，跨度至少 300ms，并晚于牌组证书或重新取得牌行的时间。只在数量变化唯一解释已看到的牌组时提出事务：新增完整一手；保留原槽位的旧手扩展；或原行／正向空行返回且数量独立确认未变时忽略假超集。它不根据余牌数构造牌的点数或花色。

有限 journal 最多四组、合计不超过 27 张。后续重复组需要正向空行边界；颜色闪动、残缺子集、展示扩展不能冒充下一手。到达安全边界仍无法解释时保持该家待确认，不丢弃早先记录去记录后面某一手。

候选事务可重复提出；调用方验证容量、原事件及序号并原子提交成功后，才能清除 journal。提交失败不能消费证据，不能出现一半扩展、一半追加。

## 遮挡及结束

独立定位的局部遮挡不得永久封锁无关座位的 journal。对局部遮挡建立的全局检查点，应将已经由单家 journal 管理的座位排除；其未确认数字仍由原 journal 负责，不能反过来要求该家重新显示过时的原牌面来解锁其他家。

普通待确认期间维持最后确认值并继续处理有证据的事件。真实信息缺口不能靠改变提示文字解决。结束、回大厅、新一局边界均须处理 journal；仍有未确认记录时，终局结果必须标记未核实，不得只因出现结算就宣称完整正确。

终局牌证明不能在账本无法接收它时被提前消费。掼蛋双出后的自动三游并不证明该玩家实际打完，不得把暴露的剩余手牌记为出牌。

## 输入恢复与短动画

可见性恢复不等于已经有有效游戏像素。原局已 RECOVERING 且有真实可见性／尺寸断点时，BETA 可有限重接原投影接收端；不能把普通识别异常当成断点授权。资格、健康取消和排队执行须持同一 sessionGuard，按原局、epoch 和固定期限再次确认。恢复输入不能重置账本或重建未看到的出牌。

完整三次强读取后出现其他未归属牌时，可在同一事件版本下短暂保留普通牌组，歧义帧不提供任何票数。保留总寿命、连续歧义长度与 OCR 原来源年龄分别有界；不能把较晚的送达时间当成新的数量来源。放宽条件只能作用于已经取得该保留资格的候选，不得整体降低普通确认阈值。

## 必要回归

每次修改检查事件、座位、顺序、牌的多重集合和牌池，不能只检查程序没有崩溃或最后回到等待界面。保留正常会话连续运行，不在中间重置检查点。

新增恢复路径同时覆盖：其他家／自己继续出牌、旧行与新行、同值重复、临时低分和残缺、数量噪声与缓存来源、短歧义、局部遮挡组合、真实采集缺口、提交失败重试、终局未核实和跨局清理。已有正常素材通过不能替代这些故障测试，也不能替代必要的本版真机及实战验收。
