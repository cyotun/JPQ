# C4 候选版：后台保存与画面复制优化

实施与电脑验证：2026-10-22 至 2026-10-23。

后续复查补修了关闭、导出、日志轮换和诊断写库失败的异常路径。这份报告对应初始 C4 构建，保留作对照；后续手机验证使用 [C4.1 复查修复包](candidate-c4-review-20261023.md)。

本轮按用户要求先完成电脑测试，不接入手机、不进入真实游戏。稳定版 v0.2.26 的安装包、签名和回滚材料保持独立；不发布服务器更新。

## 修改范围

- 牌局保存：识别线程冻结完整牌局快照，后台按顺序写 SQLite。同一牌局尚未落盘的旧快照可以被更新的完整快照替代，不合并或丢弃牌局中的出牌事件。
- 诊断日志：有界后台队列、缓冲写入，单文件达到 8 MiB 时轮换并保留上一份。队列饱和时写入明确的诊断缺口记录，不能将缺失的诊断当成识别成功证据。
- 导出与清理：停止采集后等待各会话写入者排空，防止导出遗漏尾部或清理后旧任务重建文件。清理覆盖 sessions、diagnostic、capture-probes 与牌局数据库；不清理配置和更新包。
- 保留量：停止后会话目录保留 64 MiB，采集探针目录保留 256 MiB，按最旧完整目录回收；原图片保留策略不变。
- 安装更新：签名、包名和摘要验证移到后台。锁内生成唯一的已验证文件副本，再交给系统安装器，避免后续下载替换安装器延迟读取的文件。未交接副本及时清理，已交接副本保留，下一次创建时清理超过 30 天的旧副本。候选包继续禁止使用稳定更新。
- 画面转换：直接写入调用方持有的完整画面 Bitmap，省去一个中间 Bitmap 和整帧 Canvas 清除/复制。保留 RGBA 顺序、透明度归一化、行填充、裁剪位置和黑色补边；不改变采集频率、检测模型、识别阈值或记牌算法。
- 手动取证探针：已在等待位置中的探针优先保留到模型处理，后来的帧仍可退役；每个采集实例最多尝试三个原始探针，不保证每份都有模型 sidecar。普通帧继续替换旧的普通等待帧，等待容量仍为一帧。测试必须取得至少一份实际配对证据才通过，默认记牌不会启用原始探针。

## 保存与停止的约束

`AsyncRoundStore` 只接收识别线程已冻结的完整快照，后台不读取活动账本；等待区最多 21 个牌局身份，同一身份以最新完整快照替代，数据库仍保留最近 21 局。诊断队列最多 256 条，溢出有明确记录。

`SessionTrace.close()`、牌局存储关闭和证据执行器关闭均不在调用线程等待磁盘。writer lease 在最后一个排队任务和资源关闭完成后释放。采集 worker 与识别初始化任务的父 lease 覆盖延迟创建的写入者，避免停止瞬间发生“先导出/删除、后创建文件”。

`EvidenceWork.maintain` 将开始采集与导出、清理、保留量维护互斥。停止后等待旧写入者排空，最长等待 15 秒；超时会保留证据并报错，允许稍后重试，不删除尚在写入的目录。近 10 MiB 的人工日志压力测试使用单独的关闭等待屏障核对轮换文件，不改变生产维护的时间限制。

本机硬件渲染出现显卡翻译层错误，冷启动也产生过 stock System UI / Pixel Launcher 无响应弹窗。这些轮次没有计入系统采集通过，失败记录留在本机。最终采集采用 API 37、四核软件渲染模拟器；不将其耗时等同于手机性能。

模拟器耗时仅用于比较复制路径，不能换算成手机节电百分比或腾讯游戏整局准确率。完成电脑测试后，仍需手机上的采集、温度/耗电对照和整局验证。

### 复制耗时与已修正的回归

基准使用 2608×1200、带行填充的 RGBA，先预热 3 次、再交替测量旧转换＋Canvas 路径和新路径各 7 次，并逐像素检查结果。早期裁剪路径出现过约 28ms → 165ms 的真实回归，原因是直接缓冲区逐字写黑色补边；已改为数组批量填充并重跑，不保留该实现。

修正后的双核软件模拟器中，整帧中位数为 18.47ms → 14.41ms，裁剪为 17.49ms → 15.03ms；最终四核运行中，整帧为 12.89ms → 10.59ms，裁剪为 15.53ms → 16.23ms。结果有调度波动，不能声称所有布局均提速。可确定的结构变化是减少中间 Bitmap 与整帧 Canvas 清除/复制；实际功耗收益留待手机对照。
