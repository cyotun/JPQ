# 测试数据保留与清理

每轮修改和验证完成后清理非必要测试数据，避免历史导出不断占用硬盘。此规则同样适用于 BETA 的电脑回放和手机非对局检查；不通过清理掩盖尚未解决的问题。

## 必须保留

- 正式标签、源码、签名身份、正式 APK 及其哈希和回滚发布记录。
- 用户提供的原文件，以及尚未解决问题的原始日志、截图和诊断。
- 当前回归使用的唯一输入、来源清单、来源哈希和最终结果。只保留回放结果不能替代这些输入。
- 最近实战证据；完成审计前不压缩取舍其中的原始图片。
- 能说明检查结果的最小非对局采集样本，包括原始图像、转换图像、相关元数据和会话轨迹。

## 清理流程

1. 先按目录和文件生成只读空间清单，逐一确定已过期的重复导出、重复解压或非对局采集；不按模糊名称批量删除。
2. 对非对局大 ZIP，可生成新的精简 ZIP，保留全部 JSON/JSONL 轨迹与元数据，以及指定采集探针的全部原始成员。若有其他回归引用的图片，也必须保留。
3. 原 ZIP、每个保留成员、新 ZIP 均记录 SHA-256。重新读取新 ZIP，逐成员验证内容和 ZIP 完整性，先持久化清单，再删除清单明确列出的原 ZIP。
4. 字节完全相同的导出只删重复副本。必须再次验证留下的原件，且该原件不能同时出现在本批删除计划中。
5. 记录实际释放的字节数、删除范围、保留位置和未执行项目。历史文档中的旧路径保留为来源标识，通过清理清单找到替代精简文件。

`tools/android/compact-phone-test-evidence.py` 默认仅检查计划。实际应用必须显式传入 `--apply`；仅处理已核实的过期非对局目录，不递归删除。当前保护最近实战及 C4.5/C4.6/C4.7 目录。每个清理批次需主代理复核具体文件，不把这个工具当作自动保留期限策略。

测试数据、清理计划和详细成员清单留在本机；GitHub 仅保存工具、规则和不含私人素材的汇总。服务器继续只提供 APP 更新。
