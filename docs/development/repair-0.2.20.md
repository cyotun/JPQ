# 0.2.20：开局、自己出完后的连续记牌与共享清理

候选版本 `0.2.20-regression` / code22。修复尚未通过完整验收，未发布为稳定更新。原始诊断 ZIP、截图与全部失败记录保留本机。

## 已定位的真实原因

- 首次实局在开局加倍期间，悬浮条短暂越过出牌保护边界，旧适配器丢弃整帧；恢复时没有足够证据重新接上原账本，整局停在重新核对。不能通过忽略遮挡或清空账本来解决。
- 后续 J 级牌局中，一个红 5 的牌角产生低置信、狭窄且完全内含的重复框。两张 3 打出后，手牌被错误读成 19 张而非 18 张，因此自己的出牌未能提交。陈旧的手牌账本又使最后两张牌不能跨队友视角关联，随后持续核对。先出完后停记是下游症状。
- 另一局发牌动画中，抬高的自己的 A 暂时被分给上家；完整 27 张牌出现后，空区守卫仍检查这个实际属于自己手牌的旧位置，始终无法建立基线。
- 服务没有处理最近任务划掉；旧清理链中任一步释放抛异常，都可能跳过屏幕共享停止，且关闭标志阻止重试。

## 本批改动

局部遮挡保留独立可见的手牌、出牌区域及数量来源，被遮挡区域仍禁止提交。开局恢复新增严格的倍率选择阶段证明：原 27 张牌不变、三家可见空、无任何已提交事件、两份不同 OCR 源且间隔至少 300ms。OCR 来源帧本身及其后连续画面必须清晰；缓存结果不能重复投票。恢复沿用原账本，不推测漏牌。

局部遮挡采用明确的座位集合，只在没有其他画面异常、手牌可见时启用。在遮挡期间可以积累三份独立且未变化的三家余牌数量，但不能提交出牌或恢复显示；遮挡消失后，还必须验证当前手牌、数量和桌面与原账本一致。缓存来源只能交付已经成立且仍新鲜的证明，不能增加票数。未知画面、采集缺口、调整页面和归属冲突仍清除证明。牌角外用于背景采样的 `.005` 扩边不再单独判定实际遮牌；完整可能出牌区域及实际牌角交叠保护保留。

共享手牌分区入口剔除同牌、严格内含、明显窄小且置信差足够大的重复牌角，保留合法堆叠、相邻重复牌和部分交叠。开局临时误归属则通过同一个牌角的点数、颜色、几何、手牌列连接及连续完整 27 张证据回收，仅影响该临时区域，不能修改正式牌局的出牌。

划掉最近任务时停止共享；资源逐项容错释放，旧会话回调不能关闭新会话。普通返回桌面仍保留后台记牌。手机检查补充实际任务移除和系统共享释放验证；配置备份独立落盘，使测试进程中断后仍可恢复原配置。

开启本地诊断时，保存的每张图片增加同名 JSON，绑定捕获输入 elapsed 时间、帧号、图像时间戳、尺寸、未舍入的遮罩与 JPEG SHA-256。已跟踪牌局的零检测/未知画面也保留诊断图，不再因没有识别出手牌而丢弃故障瞬间。导出仍仅在本机，图片与旁录一起受空间配额管理。原来的异步文件写入时间不足以对应动画中的精确帧，旧记录不能反向补造这项证据。

## 验证边界

每批代码修改后，重新执行全部 33 份锁定来源、153,200 帧及核心测试、构建、Lint；新增故障来源单独回放并保留 ZIP、trace、tape 和图片哈希。旧日志缺少新 OCR 源信息时保持未知，不能补造时间戳使恢复通过。

## 2026-10-18 手机预检与 0.2.21

手机连接后安装了 0.2.20，随后改为 `0.2.21-regression` / code23。所有操作均为无对局检查，没有启动游戏牌局，没有同时创建电脑录像、截图采集或第二个投屏。

显式 GPU 模型构造在手机保持亮屏时未返回；该次运行被终止，不能算 GPU 通过。默认启动原来可能依据历史资格标记选择 GPU，原生构造等待不能依靠异常回退取消，因此生产默认固定 CPU，GPU 仅保留显式、停止采集时的离线测试入口。重新安装后，故意写入匹配的旧 GPU 标记再创建默认模型，CPU 初始化及八张检测样本通过。此改动是避免启动进入这条不可取消路径，不是认定所有本轮等待均由 GPU 引起。

手机有一次核心检查的 76 项报告包含三项假设跳过，不能计为 76 项实际通过。启用真实截图参数重跑后，75 项实际通过，一项诊断归档检查未启用；另一次组合运行在渲染处等待，隔离渲染、最小 OCR→渲染组合及后续整组均通过，尚未得到该等待的稳定复现。启用诊断归档检查后又出现等待；级牌截图组也在前两项通过后等待，不能把这些不完整运行当作通过。

为继续定位，增加只读取测试进程的显式线程监听器，记录取栈前的阶段标记，避免把“未生成栈文件”误判为进程被系统冻结。诊断归档检查改用测试专有文件、数据库和偏好，不再为核对一条健康记录而先压缩全部个人历史资料；调用仍是生产归档实现，未删除或更改个人素材。这项测试并不验证大体积个人历史资料的实际导出耗时。

手机 UI 测试也补齐失败路径：无条件请求停止，确认应用状态、系统投屏、服务和持续通知全部消失；持久备份同时保存诊断开关，兼容已存在的旧版显示配置备份。UI 脚本明确启用首页检查，并把假设跳过视为未完成。
