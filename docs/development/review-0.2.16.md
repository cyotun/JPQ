# 0.2.16 后续代码审查与测试前修复

2026-10-15。审查范围：`b360a0f` 的级牌 OCR／证据恢复、`a5e0ec4` 的共享范围实验，以及它们与当前采集／提醒的连接边界。本次没有启动手机实验或真实对局，保留用户“稍后进行”的安排。

## 已确认并修复的问题

### P1：实验窗口归属与实际使用条件不一致

原工具由同一个测试应用创建底图和覆盖层。即使观察到包含或排除洋红色，也不足以验证实际“共享游戏应用、记牌器属于另一应用”的条件。现在增加独立测试辅助包 `com.cyotun.jpq.scopeoverlay`；采集／底图继续属于 `com.cyotun.jpq.tests`。检查实际 UID 不相同，辅助服务受签名权限保护，并核验发送 UID 和会话 ID。

辅助程序只画主屏的不透明洋红窗口，不含采集、文件或网络能力。两个进程都明确使用主显示屏的视觉 Context，并报告实际窗口坐标。采用 [Android 绑定服务](https://developer.android.com/develop/background-work/services/bound-services) 和 [显示屏窗口 Context](https://developer.android.com/reference/android/content/Context#createWindowContext(int,%20android.os.Bundle))；辅助层断连／失去心跳后清理。只有测试包被选为共享对象；辅助包不能被当作共享目标。

### P1：结论混用了不同位置、尺寸及不独立的帧

原工具累计所有旋转／移动后的 present/absent 数量，且“覆盖后至少两个动态计数”可以来自未参与绿区／洋红区统计的其他帧。尺寸改变或局部静止时，统计可能达到条件而没有同一条件下的独立证据。

现在原始图像时间戳必须递增；基线必须有两种计数。覆盖后的证据必须来自同一 reader 代次、图像尺寸和实测窗口位置，并等待位置稳定 600ms。三幅合格 present 或 absent 帧自身必须包含至少两种计数；混合结果保持不确定。旋转／移动立即清掉旧结论，无需等待下一帧。异常终止最终结论降为 INCONCLUSIVE，原始像素证据另存供审查。

### P2：断帧时清理和实验结束后的交互不完整

原来的 5 秒底图丢失检查只在收到图像时执行；完全不再产生图像时，只能等待总超时。现在独立定时器处理前台丢失、重复静止图和彻底断帧。辅助窗口有独立心跳、解除绑定和 90 秒硬上限；采集侧拒绝过期的窗口状态。

修复自动结束后“开始”按钮仍禁用的问题；不在测试页面前台时不打开延迟授权窗口；撤销／超时后迟到的授权结果直接丢弃。
