## 已修复的记录缺口

- 队友完整手牌经多帧确认后，手牌减少量与当前完整出牌完全一致，可独立证明下一手；解决同点同色连续出牌被当成旧牌的问题。每个账本版本只消费一次证明，遮挡、跨捕获中断、不同位置或不匹配牌面均拒绝。
- 自己最后一手的四票牌面与三票手牌差额确认，不再被其他座位的无归属动画一起清掉。外部歧义牌仍不写入。
- 已确认牌组的扩展，只有旧牌逐张位置保持一致、新增部分完整且连续稳定时，允许三帧确认；普通新出牌保持四帧。
- 头像旁持续存在的「加倍」标签不再触发新局。真实控件必须位于中央、具有合法几何、至少两个不同选项，并有实际操作区选项；支持截图中的 `加倍×2` / `超级加倍×4`。
- 活跃局被替换还需要上述控件证据、稳定的新 27 张手牌、三家可见空桌。单次场景枚举或重复 OCR 颜色变化不能清空账本。同一开局阶段保留保护。
- 观察器接入已有检查点时，续用已有事件序列号。
- 容量冲突的新候选不再使最后有效账本永久进入锁定状态；保留检查点并等候独立复核，不写入溢出牌，也不消耗事件序号。物理容量和每家 27 张上限仍照常检查。

这些修复来自实际尾段：连续大王、最后一张 3、队友最后四张、自己的四张 K，以及不足四票即清台的顺子补全。没有按结果页补造最后一张或修改初始手牌。

## 独立余牌数量复核

原物理位置检查点缺少连续证据时，仍然保留账本，不按时间自动宣告恢复。新增游戏自带「剩 N 张」角标的独立数量证明：

1. 只接受三家指定位置、金色底板、未被遮挡的完整角标，不把昵称、倒计时、名次或孤立数字当成余牌。
2. 异步 OCR 请求时复制有限的角标区域。使用结果前，当前角标整个文字框必须与源像素逐像素一致；金色背景保持不变不能证明旧数字仍有效。没有源像素绑定的结果不能参与恢复。
3. 所有仍有牌的外部玩家数量必须与检查点一致，自己的手牌也须一致，牌桌各区均可见且没有新的矛盾牌组。至少三个不同 OCR 源、时间跨度不少于 300ms，重复使用同一 OCR 帧不加票。
4. 每次新的采集中断都会清空该证明并推进独立时间截止点，不能把中断前两票和中断后一票拼在一起。
5. 自己出完后，若中断前已有两帧完整队友手牌，允许用「旧完整手牌 − 新完整手牌 = 当前直接看见的完整出牌」证明队友的新一手。其他仍有牌的玩家必须各自提供相同源图、未变化的余牌角标。该证明也需要三个新 OCR 源和至少 300ms；有队友角标时，它必须与新手牌数量一致。
6. 新一手和恢复状态由账本一次性验证、写入；任何容量、事件 ID 或序列号矛盾都保持原检查点，不先显示旧数字再补记。成功后更新该手的画面锚点，后续帧不会再次计入。

该路径复用已有 OCR，且仅在核对中断期间复制角标图像，普通对局和启动不增加这项图像分配；没有新增网络识别、诊断上传或第二路投影。像素变化时宁可暂不采用数量证明，继续等候其他有效证据。

历史固定素材没有保存这一新增数量和源像素证据，不能为旧回放填入假数量来证明此路径成功。桌面核心测试和编译已覆盖，新增 Android 像素/OCR 检查仍需在手机执行。

针对实际的队友九张变四张尾段增加集成检查：完整九张经过确认，中间七张缺字没有替换种子，缺图后直接看到的五张与差额一致，再以两位对手各剩五/六张的独立角标复核；仅计入这五张，随后连续相同画面不重记，再出两张仍只计入一次。没有角标或没有合格完整种子均不恢复。构造测试用于验证算法约束，不冒充该历史局缺失的实际 OCR 证据。

独立复核还修正了两点：物理位置恢复路径显式拒绝捕获中断和无归属帧；同花顺容量诊断中的三家余牌数量使用与界面相同的队友剔除范围，避免日志与实际计算范围不一致。

## 级牌提示与剩余验收阻碍
