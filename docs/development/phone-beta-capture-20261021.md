- 手机：2509FPN0BC，Android 17/API 37、澎湃 OS 4；序列号不写入公开报告。
- Beta：`com.cyotun.jpq.candidate`，桌面“记牌器·候选”，28 / `0.2.26-regression-candidate`。
- ARM64 安装包：`artifacts/记牌器-0.2.26-beta-单应用采集.apk`，SHA-256 `b70a6a1643c4a88651e55bd755d67c823ea62f52ac58e79992d4267e525555ad`。这是既有 C2 二进制，本轮未再改生产代码或替换识别模型。
- 稳定应用 `com.cyotun.jpq` 未覆盖，版本/更新时间不变；实际安装 APK 哈希和 `v0.2.26` 回滚包校验通过。候选更新渠道禁用，未发布到稳定服务器。
- 候选固定 FULL/CPU；25 项手机检查包含实际 CPU 检测样本、颜色转换、OCR、隔离契约及采集间隙生命周期。**25 项全部通过**，其中 CPU 样本中位耗时约 114ms；这不是整局准确率或端到端延迟指标。

所有行均通过实际候选 CaptureService、正常系统授权和同一份 ARM64 应用；系统 owner 是候选，scope 是 `RECORD_CONTENT_TASK`。每轮均在连续处理至少 10 帧、再等待 5 秒后取三张新原始图，保持 30 秒，正常停止，导出本地诊断并确认投影为 null。

## 启停、临时配置和失败记录

- 实际正常共享后，返回 Beta 首页显示“停止记牌”；点击后共享为 null，首页恢复“开始记牌”。返回自己首页导致游戏 task 暂不可见属于预期，不把此时的停帧当作大厅故障。
- 从最近任务划走**候选自己的任务卡**，候选卡消失，共享为 null。最初手势触发了系统任务锁定，随后先恢复未锁定，再以完整关闭手势验证；没有划走游戏或稳定版。
- 测试前备份候选显示配置和诊断开关，测试后恢复原始值，原 USB 保持亮屏值恢复为 15。临时浮窗工具卸载，临时测试画面包恢复成正常 `releaseAndroidTest` 包；保留 Beta 与原稳定版。
- 初始后台 OCR 检查受 HyperOS 进程冻结影响，前台重跑整套 25 项通过。第一轮取样在采集结束后的 ZIP 导出阶段被冻结而超时，不能算通过；脚本改为确认共享结束后仅前置候选首页，让导出结束，再完整重跑。所有失败记录保留。
- 游戏系统选择器同时有最近任务卡和应用列表同名项，脚本优先唯一可点击卡，仍严格核对最终目标包/UID，不凭名称宣称已选中正确应用。
- 手机共享存储中的远端临时截图/UI XML 逐次清理；本机截图和 UI XML 副本作为证据留在忽略目录。

## 复现和下一步

手机专用入口为 `tools/android/start-phone-candidate-consent.ps1`、`tools/android/run-phone-candidate-sampling.ps1`。脚本只接受本次明确授权设备；`-Target game` 必须由操作者先确认停在大厅、没有正在进行的对局，并显式传入 `-GameLobbyConfirmed`。这是操作者确认，不是脚本自动场景识别。取样脚本会启动插桩并在末尾停止共享，**绝不能在实局运行**。`-Mode shade` 展开通知面板；`-DragCounter` 从系统实际窗口边界拖动候选条，不能用旧固定坐标代替。最终共享为 null 是取样脚本成功的必要条件。

取样脚本会导出完整候选本地诊断，`host-scope.json` 明确归档范围；此 ZIP 仅供本机排障。辅助浮窗在每轮启动前需已安装并获得悬浮权限，正式实战前已移除。

上述非对局检查后，已以当前 ARM64 Beta 进入真实对局，结果为全程无记账，判定失败。后续必须先完成 [失败分析与诊断门槛](candidate-c2-failure-20261021.md)，不能直接复用当时的实局就绪结论。实局期间只读日志和应用自身诊断，不启动录像/第二投影、不安装/插桩、不操作游戏或修改配置。整局后核对开局、逐手扣减、自己先出完后的队友视角、同花顺及结算；C1 失败仍留档，不以本次非对局结果抵销。

本节为实局前的非对局检查记录；后续整局失败，当前不再标记为可用 Beta。降耗只包含既有诊断懒构造等不改变识别节奏的改动，尚未做断开充电且条件一致的温升/耗电 A/B，不能给出节电百分比。
