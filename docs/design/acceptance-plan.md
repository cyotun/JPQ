# 开发里程碑与验收方案

状态：提议验收门槛，全部性能和准确率数据目前均未实测。

当前交互与覆盖基线见 [PRD v2](PRD.md)，新增 D1–D4 待用户确认。

## 1. 开发前准备

设计经用户确认后开始。首先读取两部手机实际 Android API/系统构建号、大掼蛋包名与版本、屏幕捕获尺寸和常用游戏模式；验证系统允许获取游戏画面与悬浮显示。

样本至少包含完整一局的发牌、贡牌/还贡（如有）、各家正常出牌、不出、自家出完切到队友手牌、结算和下一局。两副牌的所有普通点数、大小王、必要花色、重叠牌面与长牌组需要覆盖。七张截图用于界面和静态结构分析，不能替代连续出牌样本。

样本标注按“玩家、出牌事件、物理牌面、发生时间、阶段”建立人工真值。原始私人录屏保留本地；可再分发的测试数据单独管理来源。

模式覆盖按大厅截图入口检查：经典、传统、不洗牌、炸弹翻倍、双级牌、私人房、组队、赛事。记录各入口实际规则与布局，复用的玩法标明对应关系，有差异则补充回放；不能只测经典就宣布完整适配。无法覆盖的组合向用户报告并确认。

## 2. 分阶段交付

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| M1 识别验证 | 数据覆盖清单、离线回放对照、区域/牌面识别方案选择 | 能区分各家、贡牌与队友展示；模板/模型路线有真实样本依据；缺失牌类明确列出 |
| M2 Android 基础 | 可安装的采集/悬浮窗版本，权限与停止流程 | 两部手机可以授权、采集、显示、拖动、停止；采集失效不崩溃、不继续假更新 |
| M3 完整记牌 | 基线、自动交叉校验、事件去重、统计历史、新局处理与显示调整 | 通过标注整局回放；相同牌二次出不会漏记；贡牌及队友展示不污染统计 |
| M4 真机交付 | 自用 APK、源码、安装/使用说明、实测记录 | 两部手机各完成至少 10 局对照；完成延迟、触摸、资源和系统中断测试 |
| M5 自动更新 | 独立 Cloudflare 更新服务、发布流程、App 更新功能 | 两部手机从旧版更新到新版；校验失败拒绝安装；现有项目未被修改；费用/额度符合用户免费约束 |

每阶段用 Git 保存源码、功能说明和实际验证结果，推送用户指定仓库。出现失败先分析原因再推进，不能用“可安装”代替“可稳定记牌”。

## 3. 必测正确性场景

| 场景 | 必须满足的结果 |
| --- | --- |
| 标准首局 | 稳定的初始 27 张只扣除一次；三家未知牌合计为 81 |
| 自己正常出牌 | 手牌外剩余不因自家打出的同一张牌再减少 |
| 同一手牌停留多秒 | 只记一条历史 |
| 同一家后续又出相同牌组 | 在新事件边界证据充分时分别记入 |
| 快速动画、短暂遮挡/空帧 | 不因闪烁产生额外出牌或误判新局 |
| 不出 | 不扣牌；如展示不出状态不计入已出张数 |
| 进贡/还贡/抗贡 | 不当正常出牌，基线时机正确 |
| 重叠、多行、王炸/长牌组 | 张数和点数正确；大小王不混用 |
| 级牌/红心级牌 | 真实物理点数扣除正确；无法确认算识别测试失败，不靠人工修复 |
| 自己出完后显示队友手牌 | 不重建自家基线，不清空三家历史 |
| 结算明牌/下一局 | 不把结算明牌记为正常出牌；新局明确隔离 |
| 识别冲突或漏采集 | 先自动复核；不能恢复则当前计数未知、等待下局。完整测试对局出现此状态算失败 |
| 中途才启动 | 未完整观察到的历史不被伪装精确；等待下局，无人工补齐入口 |
| 普通牌计数颜色 | 4 张及以上红色，1–3 张白色，0 张淡灰；同屏可同时出现三种颜色 |
| 王牌与不确定计数 | 按原 APK：大王、小王各自 ≥2 红色，1 张白色，不检查组合；未知/冲突不标红 |
| 着色随统计变化 | 4→3 自动由红转白；新局采用新基线重算颜色，无手动修订分支 |
| 牌序默认值与拖动 | 掼蛋 2 在末尾，斗地主显示默认 2 在 A 前；15 类牌无重复缺失，重排后每种牌的计数/颜色仍正确 |
| 配置分别保存 | 切换玩法、重开应用保留各自牌序；恢复默认不覆盖其他玩法 |
| 尺寸/字号调整 | 八项分别生效、即时预览、保存恢复正确；退出不保存可回到原布局；小尺寸不裁切计数 |
| 关闭右侧记录 | 标签、黄色数字、历史及触摸占位全部消失，条宽缩短；识别、扣牌和账本继续 |
| 重新开启右侧记录 | 显示隐藏期间的完整出牌历史，恢复完整模式宽度/比例；仅计数模式宽度不被覆盖 |
| 原 APK 默认显示参数 | 初始值和恢复默认与提取的浮点参数一致；按原范围限制滑块；不将 115% 等截断显示值当作原常量 |
| 调整与本局重置 | 调整页重置只改设置草稿；顶部本局重置按确认后的流程归档并等待有效基线，不共用操作 |
| 无手动改牌入口 | 首页、设置、悬浮条和工具均无手牌加减、改牌、撤销与补记；不能以人工修正后数据作正确性结果 |
| 自动复核与重读 | 同一画面重读不再提交一次；唯一完整证据恢复才更新统计，守恒条件不能单独用于猜牌 |
| 悬浮窗字体与色值 | 钉钉进步体、原金色/深灰/红色与零透明度；细边框、渐变表头、圆钮、行距和竖条滑块符合原样 |
| 备份导入失败 | 不破坏现有设置；不导入权限 token、录屏、密钥或虚构已授权状态 |
| 开始后等待牌局 | 左上角隐藏按钮与金色两行提示；尚未初始化时无虚假牌面计数，发牌/贡牌完成后自动切换 |
| 等待期间隐藏/恢复 | 隐藏不停止初始化；后台已进入牌局时，恢复直接显示当前记牌状态 |
| 交互一致性 | 逐项对照原启动、隐藏、拖动、尺寸/牌序两页、保存退出、重置行为；差异先列出并经用户确认 |
| 断网/更新服务失败 | 继续使用已安装版本记牌；检查失败不能阻止开始记牌或清空本局 |
| 更新完整性与身份 | 截断、哈希/签名不符、包名不符、降级版本均不安装；有效更新保留本地配置 |
| 更新签名载荷 | 中文、换行、emoji 和 JSON 空白/字段顺序向量跨发布工具/Kotlin 一致；重复字段拒绝；篡改验证失败 |
| 更新分片与发布切换 | Range 响应符合版本与大小；旧版本下载失效重新检查；200 不追加已有分片，不能混合两个版本 |
| 更新不打断记牌 | 按 D4 确认后的策略检查/下载/安装，对局期间不弹安装或结束采集；204 显示暂无发布版本 |
| Android 安装授权 | 满足平台条件时尝试自更新；系统要求用户操作时正确显示安装确认，不卡在后台 |
| 服务部署隔离 | 只操作 JPQ 专用项目、存储和发布配置；记录与原项目对照，确认无覆盖/改绑 |

## 4. 设备、系统与体验

设备按用户提供的两部手机实测，系统按实际安装版本记录。若需要 OS 3 与 OS 4 都通过验收，要分别有相应版本的测试记录，不能从一次测试推断两版兼容。

测试矩阵覆盖左右横屏、可用分辨率设置、导航模式、安全区、单应用/整屏共享、从首页切到游戏、通知弹出、悬浮窗展开/隐藏、右侧记录开关及两个模式分别调大小、锁屏和系统停止共享。后台被结束后的处理也要记录。

| 指标 | 初始目标（待实测确认） | 测量方法 |
| --- | --- | --- |
| 记牌正确性 | 两部手机各至少 10 局并覆盖目标模式/阶段，逐手牌面、归属、历史与剩余均零错漏；无法确认及非预期中断也算失败 | 独立真值/完整回放逐事件比对；失败保留报告并修复回归，不能人工修正或删样本通过 |
| 更新延迟 | 稳定牌面出现到悬浮显示的 P95 不高于 1 秒 | 对齐录屏时间线与本地事件时间 |
| 游戏触摸 | 展示模式不阻断悬浮条外游戏控件，菜单关闭可恢复正常操作 | 实际点击所有高频控件和边缘区域 |
| 会话稳定性 | 60 分钟主动使用不中断；系统主动停止时正确释放并提示 | 手机连续会话、日志与资源记录 |
| 内存 | 无持续增长；初始参考上限 250 MiB，按选型调整并记录 | 多局运行前后测量 |
| 增量耗电 | 初始目标 30 分钟增加不超过 5 个电量百分点，属于估计门槛 | 相同亮度、网络、游戏场景，开/关工具成对测试；重复比较 |

这些是验收目标而非已达到的性能。正确性门槛必须结合样本覆盖表；一旦失败或新增皮肤/游戏版本导致变化，保留明确的适配状态与回归记录。
