# 开发里程碑与验收方案

状态：提议验收门槛，全部性能和准确率数据目前均未实测。

## 1. 开发前准备

设计经用户确认后开始。首先读取两部手机实际 Android API/系统构建号、大掼蛋包名与版本、屏幕捕获尺寸和常用游戏模式；验证系统允许获取游戏画面与悬浮显示。

样本至少包含完整一局的发牌、贡牌/还贡（如有）、各家正常出牌、不出、自家出完切到队友手牌、结算和下一局。两副牌的所有普通点数、大小王、必要花色、重叠牌面与长牌组需要覆盖。七张截图用于界面和静态结构分析，不能替代连续出牌样本。

样本标注按“玩家、出牌事件、物理牌面、发生时间、阶段”建立人工真值。原始私人录屏保留本地；可再分发的测试数据单独管理来源。

## 2. 分阶段交付

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| M1 识别验证 | 数据覆盖清单、离线回放对照、区域/牌面识别方案选择 | 能区分各家、贡牌与队友展示；模板/模型路线有真实样本依据；缺失牌类明确列出 |
| M2 Android 基础 | 可安装的采集/悬浮窗版本，权限与停止流程 | 两部手机可以授权、采集、显示、拖动、停止；采集失效不崩溃、不继续假更新 |
| M3 完整记牌 | 基线、事件去重、统计历史、新局处理、调整和纠错 | 通过标注整局回放；相同牌二次出不会漏记；贡牌及队友展示不污染统计 |
| M4 真机交付 | 自用 APK、源码、安装/使用说明、实测记录 | 两部手机各完成至少 10 局对照；完成延迟、触摸、资源和系统中断测试 |

每阶段用 Git 保存源码、功能说明和实际验证结果，推送用户指定仓库。出现失败先分析原因再推进，不能用“可安装”代替“可稳定记牌”。

## 3. 必测正确性场景

| 场景 | 必须满足的结果 |
| --- | --- |
| 标准首局 | 稳定的初始 27 张只扣除一次；三家未知牌合计为 81 |
| 自己正常出牌 | 手牌外剩余不因自家打出的同一张牌再减少 |
| 同一手牌停留多秒 | 只记一条历史 |
| 同一家后续又出相同牌组 | 在新事件边界证据充分时分别记入 |
| 快速动画、短暂遮挡/空帧 | 不因闪烁产生额外出牌或误判新局 |
| 不出 | 不扣牌；如展示不出状态不计入已出张数 |
| 进贡/还贡/抗贡 | 不当正常出牌，基线时机正确 |
| 重叠、多行、王炸/长牌组 | 张数和点数正确；大小王不混用 |
| 级牌/红心级牌 | 物理牌面扣除正确；无法确认的牌有待核对状态 |
| 自己出完后显示队友手牌 | 不重建自家基线，不清空三家历史 |
| 结算明牌/下一局 | 不把结算明牌记为正常出牌；新局明确隔离 |
| 手动撤销/修改/补记 | 历史与统计同时重算，恢复操作可得到原结果 |
| 识别冲突或漏采集 | 出现待核对，负数不被悄悄截为 0 |
| 中途才启动 | 未完整观察到的历史不被伪装精确；默认等待下局或人工补齐 |

## 4. 设备、系统与体验

设备按用户提供的两部手机实测，系统按实际安装版本记录。若需要 OS 3 与 OS 4 都通过验收，要分别有相应版本的测试记录，不能从一次测试推断两版兼容。

测试矩阵覆盖左右横屏、可用分辨率设置、导航模式、安全区、单应用/整屏共享、从首页切到游戏、通知弹出、悬浮窗展开/隐藏、锁屏和系统停止共享。后台被结束后的处理也要记录。

| 指标 | 初始目标（待实测确认） | 测量方法 |
| --- | --- | --- |
| 记牌正确性 | 两部手机各 10 局，逐事件对照；无人为纠正时牌面与归属全部正确；存在缺失场景不能宣布完成覆盖 | 独立人工真值/回放比对，逐局报告失败及待核对项 |
| 更新延迟 | 稳定牌面出现到悬浮显示的 P95 不高于 1 秒 | 对齐录屏时间线与本地事件时间 |
| 游戏触摸 | 展示模式不阻断悬浮条外游戏控件，菜单关闭可恢复正常操作 | 实际点击所有高频控件和边缘区域 |
| 会话稳定性 | 60 分钟主动使用不中断；系统主动停止时正确释放并提示 | 手机连续会话、日志与资源记录 |
| 内存 | 无持续增长；初始参考上限 250 MiB，按选型调整并记录 | 多局运行前后测量 |
| 增量耗电 | 初始目标 30 分钟增加不超过 5 个电量百分点，属于估计门槛 | 相同亮度、网络、游戏场景，开/关工具成对测试；重复比较 |

这些是验收目标而非已达到的性能。正确性门槛必须结合样本覆盖表；一旦失败或新增皮肤/游戏版本导致变化，保留明确的适配状态与回归记录。
