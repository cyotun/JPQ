# 开发就绪核对

2026-10-11。核对基线为 [PRD v4](PRD.md) 及六张静态设计图。本轮检查仓库与本机构建工具，没有运行原 APK、连接手机或重新检查 Cloudflare 控制台。

## 结论

主要功能、页面、显示参数和状态规则已足以进入开发，不需要再补一轮整套界面设计。用户最初要求设计确认后开发，四项新交互已合并提出一次整体确认，收到确认后执行现稿；当前文档不将尚未收到的回复标为已批准。

“可以开工”与“已经验证能稳定记牌”分开。识别路线和游戏适配参数需要真实样本验证，App 尚未构建，不能把参考 APK 中的模型/类名当作自研功能已完成。

## 开发执行顺序

1. 准备并固定安卓构建环境；建立工程、配置、纯记账规则及基础界面，用 Git 持续保存和上传。
2. 实现采集与悬浮窗，使原风格、按钮、隐藏、两页调整和长记录扩展可以在真实手机验证；同时准备连续对局真值样本。
3. 依据完整回放选择识别路线并接入阶段/去重/记账。不得用假数据、单张截图成功或人工修正宣称自动记牌完成。
4. 完成各玩法回归、两部手机整局验收、安装包签名与独立更新下载/安装。只有实际通过后才交付稳定记牌版本。

首个可安装的基础版本用于验证权限、采集和悬浮操作；最终交付目标始终是可稳定自动记牌的 App。其余性能与兼容性以 [验收方案](acceptance-plan.md) 的实际结果为准。
