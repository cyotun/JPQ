# JPQ 技术设计 · 提议版本

状态：设计待确认，未开始应用实现。应用名「记牌器」，工程代号 JPQ。目标是复现参考 APK 在大掼蛋中的相关行为，做到全自动准确记牌，并用完整回放验证。用户已取消全部手动纠错，保留 App 自动更新。

交互基线见 [设计确认稿 v3](PRD.md)。重置按钮显示开关与可选双击隐藏已由用户指定；工具/拖动入口与自动复核/更新时机的其余提议以 D1–D4 审阅结果为准。

## 1. 架构与扩展

```mermaid
flowchart LR
  Capture[授权屏幕采集] --> Geometry[画面定位与区域校准]
  Geometry --> Vision[本地牌面识别]
  Vision --> Events[多帧确认与出牌归属]
  Validation --> Rules[大掼蛋阶段与记账规则]
  Rules --> Ledger[本地事件记录与重算]
  Ledger --> Overlay[悬浮窗统计与历史]
  Events --> Validation[自动交叉校验与短时帧复核]
```

拟采用：Kotlin、Jetpack Compose、WindowManager 原生悬浮窗、MediaProjection/ImageReader、协程、DataStore 设置、Room 事件记录。OpenCV 与 NCNN 属于待样本评测的候选依赖，不提前堆叠多个推理后端。

逻辑划分：

| 层 | 责任 |
| --- | --- |
| app/ui | 首页、权限、显示设置与应用更新；无改牌入口 |
| capture | 前台采集服务、资源生命周期、最新帧处理与几何回调 |
| vision | 区域定位、牌面/花色识别、置信度、画面证据 |
| game-adapters | 大掼蛋的画面锚点、各家区域、阶段提示；后续新增游戏 |
| rules | 两副牌、贡牌、级牌、每家身份与本局生命周期；后续新增玩法 |
| ledger | 自动确认事件、观测证据与统计重算 |
| overlay | 记牌条、历史、调整面板和触摸边界 |
| data | 本地设置、事件与模型版本元数据 |
| updates | 独立 Cloudflare 版本检查、可靠下载、校验及 Android 安装流程 |

模块可以先以清晰包边界组织，确认实际规模后再拆 Gradle 模块。通用牌库/事件引擎不依赖具体截图坐标。

## 2. 采集与本地识别

优先允许用户选择只共享大掼蛋；同时测试整屏共享。单应用采集图像与物理屏幕坐标不一定相同，必须分开保存采集坐标到悬浮窗坐标的变换，处理黑边和旋转。

前台服务负责持有采集会话。注册停止、尺寸和可见性回调；只处理最新帧，及时关闭 ImageReader 图像，避免积压。分辨率变化调整现有虚拟显示与 surface；失效 token 不重用。停止后释放虚拟显示、ImageReader、模型会话和悬浮窗口。

画面识别流程：

1. 根据桌面锚点与画面比例定位有效游戏区域，校验是否为可记牌场景。
2. 划分自己的手牌、三家出牌、玩家余牌数字、贡牌/结算提示区域。
3. 屏蔽悬浮窗和会造成误识别的非牌面 UI；手动拖到识别区域时提示或回避遮挡。
4. 检测可见牌面角标，归一化尺度；识别点数、大小王和必要花色，保留位置/置信度。
5. 用几何相邻关系整理一手牌；重叠区域避免把同一牌的多个标识当作多张牌。
6. 使用多帧证据生成出牌事件，交给阶段规则验证，不直接修改计数。

拟比较两条离线路线：

- 固定皮肤的区域模板/轻量分类：成本较低，但必须实测覆盖不同尺寸、叠牌和动画。
- 轻量牌面检测 + 点数/花色分类：更接近参考 APK，需自有或可再分发的训练资产；NCNN 是候选运行时。

选择依据为标注录屏中的整局事件正确性与手机耗电，不能用几张静态截图成功识别作为选型通过。OCR 主要用于阶段提示和余牌数字，不单独承担整套扑克牌识别。

帧率初始建议：等待/静止低频，出牌活动时提高到约 6–10 次观测/秒；实际参数按性能测量调整。参考 APK 的预处理 15 FPS 是配置事实，不能直接作为 JPQ 的性能承诺。

## 3. 状态机

会话层：`未启动 → 待权限 → 采集中 → 采集失效 → 停止/重新授权`。不设置用户暂停入口。失效保留已确认账本供验证，当前数字显示未知；重新授权不能补出未观察的历史，无法恢复的本局等待下一局。

牌局层：

| 阶段 | 允许行为 |
| --- | --- |
| 等待牌局 | 不扣牌，等待桌面/手牌稳定 |
| 发牌中 | 收集候选初始手牌，避免动画直接锁定 |
| 贡牌中 | 跟踪手牌变化和贡牌提示，不生成普通出牌 |
| 初始化校验 | 27 张、阶段与牌面稳定性自动校验；证据完整才锁定 |
| 正常出牌 | 确认三家出牌事件并更新历史/统计 |
| 自家出完/队友展示 | 保留自家初始基线与席位，识别队友展示仅作旁观信息 |
| 结算 | 结束本局，保存摘要；等待下一局，不因明牌直接再扣 |
| 自动复核 | 使用已采集帧与交叉证据消除候选冲突，未确认事件不提交 |
| 本局不可恢复 | 停止本局精确统计，等待下一局完整初始化，不要求用户改牌 |

新局初始化需要组合证据：上一局结束或可靠的新局提示、稳定的新发牌画面、阶段转换。仅“看到 27 张牌”不足以认定新局，因为队友明牌/结算明牌也可能符合。

## 4. 多帧确认与去重

每家独立维护候选序列、可见牌组、上次已确认事件及重新允许记账的证据。多帧一致只是确认条件之一，不是新事件判定条件。

- 同一组牌持续显示、闪烁或动画改变位置：保持同一个事件。
- 相同牌组在后续新轮次再次出现：只要有可靠的新出牌边界，即可记为新事件。
- 边界证据来自牌面移除/替换、可靠的轮次变化、对应玩家余牌变化等；短暂空白不足以重新开启一次扣牌。
- 多个区域同时含牌时，依据玩家区域和事件上下文归属，不能仅按中心坐标猜一家。
- 若相同牌组是否属于新出牌无法区分，保留待定项并提示，不用固定冷却时间强行决定。
- 自动复核始终保留原事件身份与观测边界关联，同一画面不能因重读再提交一次。

将多帧视觉结果与玩家余牌变化、自己的手牌变化、席位区域和回合转换交叉校验。数量守恒是必要约束，不足以证明点数与归属正确。短时帧缓冲在内存限额保存；只持久化用户主动开启的诊断采样。不用余牌差值猜具体点数，也不直接沿用参考 APK 的置信票数宣称相同准确率。

建议事件标识包含会话、本局、玩家、观测边界序号和牌组指纹。指纹只是检查内容，不能独自成为永久去重键。

## 5. 牌库与计算

物理牌面结构：点数、花色（可未知）、大小王类型、识别置信度。两副牌中同点数同花色各 2 张；不可通过画面区分的副本使用数量表示，不凭空分配独立牌 ID。

默认显示未在自己初始手牌内、且尚未由三家打出的物理牌：

```text
U[r] = D[r] - H0_self[r] - P_previous[r] - P_opposite[r] - P_next[r]
```

自家已出 `P_self` 不再扣除；自己的当前手牌可用于检测自家状态与校验，但不能反复替换 `H0_self`。默认不再扣除后来画面中可见的队友手牌，否则会改变参考软件统计口径并存在重复扣除。

玩家已出总数是已确认事件张数之和；正常初始 27 张且无未跟踪转移时，其剩余为 `27 - 已出`。不满足条件时显示未知，不默认为 27。

贡牌完成后建立或刷新基线。若首版后续支持进行中的可见手牌转移，必须记录转移事件，统一重算；不能把转移当打出。

级牌和红心级牌按真实物理点数扣除；逻辑上被当作某点数使用的万能牌另存宣称信息。尚未证明真实牌面可见时，不保证花色/万能牌精确统计。

校验要求：每点数/花色不超牌库；剩余不得为负；每家张数不得异常超出；在标准完整基线下三家剩余总数与 `sum(U)` 一致。**不能把负数静默截断为 0**。冲突先自动复核；无法恢复则本局不可用，当前计数显示未知。没有手动纠正入口。

配色直接复现已读取的原 APK 方法：普通点数阈值为 4，大王/小王各自阈值为 2；达到阈值为红色，正数但未达阈值为白色，零为淡灰，未知/冲突显示 —。默认不检查王牌的跨牌种组合，用户已选择保留原配色行为。原颜色值为红色 `#FFFF3140`、白色 `#FFFFFFFF`、零计数 `#26FFFFFF`（白色透明度约 15%）；零计数须在原背景上混合，而非当作不透明 RGB。

着色只保留原软件的剩余数量提醒，不推断牌在同一家，也不把花色未知、万能牌或同花顺推断混入该规则。每次自动确认事件与新局初始化后统一计算颜色；4 到 3 立即由红变白，新局依据新基线重新着色。

## 6. 自动事件账本与回放验证

事件数据建议：局 ID、事件 ID、玩家、阶段、观测时间、牌组、置信度、观测边界、识别资产版本、自动校验结果、可选本地证据区域引用。所有记账事件由自动识别确认，无用户手动事件来源。

初始手牌、出牌、转移和结束形成自动事件序列；显示统计从有效事件计算，历史和计数使用同一真值。复核候选不直接改统计；必要时依据完整观测证据生成新账本版本，保留来源关联用于回放，不能仅因守恒条件通过而猜补漏牌。

离线回放必须输出逐事件差异表、各家历史、每步剩余和状态变化，并对齐独立人工标注。交付测试集中每次错记、漏记、无法确认与非预期中断均算失败；没有人工修正通过分支。

默认保留当前局与最近 20 局结构化账本；截图只在用户开启诊断采样时保存到应用私有目录，上限 100 MiB，提供清理入口。设置保存在 DataStore，结构化事件保存在 Room。自研应用不集成参考软件的云端上传、会员或设备标识 SDK。

联网仅增加 App 更新用途，Cloudflare 不接收手牌、出牌截图或记牌账本。更新模块失败不改变采集状态、牌局基线或本地数据。服务端部署边界与协议见 [Cloudflare 自动更新](cloudflare-update-plan.md)。

## 7. 悬浮窗与设置

默认展示条与显示调整面板分开。展示条紧贴自身可见内容，不建全屏透明触摸层；可见圆钮与内容区域分别命中，不增加常驻手柄。D2 提议长按内容区或可见隐藏圆钮打开工具，拖动内容区移动，因此没有圆钮时仍可调整和停止。Android 12+ 必须实测叠加透明度和底层触摸交付，不能只设置 NOT_TOUCHABLE。

悬浮窗保存：归一化位置、完整模式内容宽度、仅计数模式内容宽度、左右比例、牌格高度、记录行高、四项字号、牌序、三家记录可见性、`showResetButton`（默认 true）和 `doubleTapHide`（默认 false）。新增两项为全局显示偏好；旧配置缺字段按默认迁移，配置备份包含它们。尺寸参数以原人数/副数 key 为基线，新增显示模式宽度独立保存；牌序按游戏/玩法分组，位置按有效窗口几何恢复。导入时校验版本、15 类牌唯一性和尺寸边界；旋转后限制在可见安全区。首版固定三家数字为累计已出，不增加统计口径切换。

窗口可见性与牌局状态独立：展开时 `doubleTapHide=false` 显示隐藏圆钮，true 时移除它；重置圆钮只由 `showResetButton` 控制（等待界面原本无重置）。隐藏时只创建一个显示圆钮，不保留不可见主条的触摸窗口。单击显示恢复当前牌局/配置并移除显示圆钮，不停止或重建采集与账本。

按钮移除时同时去掉 44dp 按钮和相邻 4dp 间距，内容宽度/字体/左右比例保持不变；两个开关与三家开关的组合重新测量实际窗口，左侧锚点不变，不回写或覆盖保存的尺寸值。切换设置只更新显示，已隐藏时保持隐藏直至用户点击恢复。

手势识别只作用于真实展开的内容区/等待与异常提示条；按钮和工具/设置/调整预览不参加双击隐藏。按系统双击时限与移动容差处理，单击不改变数据，拖动、长按和双击互斥。长按打开工具后取消候选点击；视图/模式切换取消所有旧触摸序列，恢复按钮的点击不参与随后主条的双击。展示状态切换不得改变出牌事件、采样和牌局基线。

显示配置「显示三家出牌记录」默认为 true。关闭时移除整个右侧视图及其触摸区域、重新测量窗口，左侧锚点尽量保持；继续保留内部三家出牌识别和账本。再次开启从当前账本渲染历史。两个显示模式分别持久化宽度；关闭时禁用左右比例、记录行高及右侧计数/详情字号编辑，但不删除原值。对设置预览和正式悬浮窗采用同一布局约束，避免预览尺寸与实际不一致。

八项调整沿用用户截图：总宽度、左右比例、牌格高度、记录行高、左侧标题/数值字号、右侧计数/详情字号。滑块、拖动、保存退出、重置与退出的交互优先沿用原 APK；实现前核对原操作对应的方法和保存时机，存在无法确认的行为先沟通。

默认参数以 [reference-display-defaults.json](../research/reference-display-defaults.json) 为来源：四人两副牌使用 `Standard` 基准布局和原两副牌调整常量，沿用浮点值、范围与布局公式，不能把截图百分比反推为整数默认值。字体、行高、边框、列间距与 44dp 按钮保留原基准。原尺寸 key 实际为人数/副数，原牌序 key 为玩法；JPQ 仅在必要时扩展保存维度，默认呈现保持原样。关闭右侧后保留左侧列宽/字号，依据可见内容缩短窗口，两个模式分别保存宽度。

字体与原色值见 [显示样式证据](../research/display-style.md)。悬浮条复现钉钉进步体，禁止隐式回退后声称原字形；主界面常规文本与悬浮条字体区分。采用原深灰内容底、渐变表头、细黑边框、平面金色圆钮；调整页保留宽轨道与竖条滑块。参考字体二进制不进入仓库，发布前核实正式 APK 内嵌使用许可。

显示顺序使用稳定的牌种键列表，不依赖模型输出下标或当前列位置。掼蛋默认 `大、小,A,K,Q,J,10,9,8,7,6,5,4,3,2`，斗地主默认 `大、小,2,A,K,Q,J,10,9,8,7,6,5,4,3`；保持原拖动排序页面并按游戏/玩法保存。切换玩法时读取已保存值，自定义牌序不因新局或级牌改变被覆盖；恢复默认只重置当前玩法牌序。更换顺序不能影响计数、事件牌面或着色。斗地主顺序配置不扩大首版自动识别支持范围。

等待视图默认复现参考截图的左上角圆形隐藏按钮与金色两行提示条；开启双击时移除该按钮及占位，双击提示条隐藏。显示条件为采集有效、记牌会话已启动且本局基线尚未建立；发牌/贡牌时保持等待，稳定初始化后切换为用户配置的记牌条。隐藏是显示状态，不改变采集/初始化；恢复渲染当前状态。重新授权或错误视图不能被等待提示覆盖。新文案见产品方案。

整体交互以原 APK 为基线。新的交互优化先提出并获得用户确认后实现；反编译未完整恢复的方法以 Lua、简化指令或真机行为补证，不能凭混淆别名猜操作。

## 8. Git 与交付

研究设计在独立文档分支保存。确认后按功能创建开发分支，提交可解释的变化及验证记录，持续推送指定 origin；避免未经要求覆写远端历史。

构建工具、SDK 和依赖在实现开始时核实并固定版本。当前仅检测到系统 Git/Python，未确认 Android SDK、JDK 和 ADB 可用；设计阶段没有安装完整开发环境。实际签名密钥留在本机，不进入 Git。交付 APK、源码提交版本、安装说明及两部真机测试结果。
