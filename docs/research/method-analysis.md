## 2. 剩余牌计算

`RemainingCardCalculator.calculate` 建立牌库计数，扣除非自家已出牌，再扣自家初始手牌；自家已出跳过，避免重复扣除。

如果存在有效的“对家初始明牌”列表，则跳过对家已出扣除，改扣该明牌基线，避免两次扣除。这条路径与“自家出完后显示队友手牌”不是同一字段。还有其他玩法的返还/特殊牌调整及统一王类选项。大掼蛋正常截图统计符合普通路径。

计算方法可产生负数，原显示层将负数显示为 0。JPQ 按前述方案增加识别冲突的待核对状态，具体交互仍待确认。

## 3. 实际配色方法

反编译位置：`p000.AbstractC3740pk.m9461Y`，原混淆类名 `pk`、方法名 `Y`。读取到的分支是：普通牌阈值 4，名称为大/小/大王/小王时阈值 2；非正数淡色，达到阈值红色，其余正数白色。

原 ARGB：红 `#FFFF3140`、白 `#FFFFFFFF`、零计数 `#26FFFFFF`、计数背景 `#FF434343`。用户已选择保留原配色，因此不自行改成完整王炸组合校验。

## 4. 设置保存与默认参数

| 原符号 / 可读证据 | 确认职责 |
| --- | --- |
| `XE` / `FloatingWindowCardOrderKey(gameMode=...)` | 牌序 key 为玩法 |
| `aF` / `FloatingWindowCardOrderPreference(orderedLabels=...)` | 保存有序牌面标签列表 |
| `QE` / `FloatingWindowAdjustmentKey(playerCount=..., deckCount=...)` | 尺寸 key 为人数/副数 |
| `IE` / `FloatingWindowAdjustment(...)` | 九个内部显示系数：八项可见调整及记录标签字号 |
| `UserPreferencesManager.saveFloatingWindowCardOrder` | 更新内存状态并持久化牌序 |
| `UserPreferencesManager.saveFloatingWindowAdjustment` | 更新内存状态并持久化尺寸 |

保存列表有有效牌种过滤及去重。按用户要求沿用拖动、保存和读取行为，区分掼蛋/斗地主显示顺序；列位置不能代替识别牌种 ID。

`KE` 两副牌默认系数已读取，见 [默认参数](reference-display-defaults.json)。四人两副牌的基准为 `HR` 中的 `Standard`。`Zf0.R` 对系数限幅，按总内容宽度与左右比例分配宽度，扣列间距后计算每列宽度，再分别缩放行高与字号；按钮基准单独保留。

原滑块范围：总宽度/字号 80–135%，左侧比例 30–60%，牌格高度/记录行高 85–130%。浮点常量不能替换为截图显示的整数百分比。用户要求默认值和整体交互沿用原 APK。

## 5. 掼蛋阶段与出牌确认

真实业务 Lua 中可直接阅读 `strategy_guandan.process`、贡牌状态进入/退出、`process_player_cards`、`process_dealer_hand`、队友手牌 OCR 和新局处理函数。

确认到：贡牌期间清理待出牌缓存，不走普通出牌；四家出牌区域连续两次为空后退出该贡牌状态。“未观察到区域”与“观察到但为空”分开，未观察不能触发空帧最终确认。默认出牌确认票数为 4，运行时配置允许 2–4；设备调整由运行时策略提供。

队友展示通过“队友/对家/友方”OCR 和手牌集合关系进入自家已出完等待阶段，抑制错误新局重置，不能简化为看到新牌就重置。

预处理脚本按有效区域选择 no_active 或 packed 计划，packed 默认目标 320，预处理配置 15 FPS，并保留区域合并/遮挡分割参数。实际图像处理和推理仍依赖 native 接口，读到脚本不等于验证了手机性能。
