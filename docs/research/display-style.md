# 原 APK 的悬浮窗字体与样式证据

2026-10-11。静态方法/资源及官方字体对照结果，尚未做原 APK 真机渲染测量。本文件不包含参考 APK 的字体二进制或界面资产。

## 1. 实际字体

`AbstractC4037uF` 加载 `R.font.dingtalk_jinbuti`、`alibaba_puhuiti` 和 `din_regular`；悬浮窗相关 `AbstractC4573Zf0` 多条渲染分支使用 `dingtalk_jinbuti`。隐藏/显示圆钮的 helper `m4095g` 接收字体，采用 16sp 基准文字及原金色圆形背景。不能用普通系统字体加斜体代替后宣称已复刻。

从 [钉钉官方字体页面](https://page.dingtalk.com/wow/dingtalk/default/dingtalk/y-W5aF3_ZJwzulU0nceIl) 找到官方字体下载包。本机官方 TTF 与 APK 的 `res/font/dingtalk_jinbuti.ttf` 分别计算 SHA-256，均为：

```text
6f6a1e15f33d559ff3d0d7dcc8bd9ab25a6dbd8e9bcd29865daf7615a17ea284
```

v2 静态设计稿使用此官方字体绘制。原 APK 还包含其他字体，不把全部页面都改成钉钉进步体；首页/调整控件常规文字与悬浮条区分。

字体包的许可文件已本地读取。字体文件不上传 GitHub；免费使用不能推定为任意再分发许可。正式 APK 内嵌与发布前须核实许可覆盖方式。本轮图片为字体的渲染结果，未发布原始字体文件、修改字体或复制 APK 图形资源。生成脚本从本地 `JPQ_OVERLAY_FONT` 读取，缺失时明确报错，不隐式换字形。

## 2. 色值

`AbstractC1827cF` 的常量与内容绘制 `AbstractC5235pG0.m9389g` 对照如下。数量配色方法另见 [方法分析](method-analysis.md)。

| 部位 | 原值 / 处理 |
| --- | --- |
| 金色按钮与已出计数格 | ARGB `#FFFFE395`，RGB `#FFE395` |
| 内容背景 | `#FF262626` |
| 牌格/标签背景 | `#FF434343` |
| 表头渐变 | `#FF6D6E6E` → `#FF434343` |
| 内容边框、金色格文字 | 黑色 |
| 达阈值数量 | `#FFFF3140` |
| 其他正数 | `#FFFFFFFF` |
| 零数量 | `#26FFFFFF` 在 `#434343` 上混合，约为 `#5F5F5F`，不可把前缀透明度丢弃 |

普通点数 ≥4、大王与小王各自 ≥2 标红；没有完整王炸组合判断。红色是数量提醒，不能证明同一家持有炸弹。用户已确认保留此行为。

## 3. 布局与控件

已提取 Standard 基准和两副牌默认参数，见 [精确参数 JSON](reference-display-defaults.json)。原基准 44dp 圆钮、4dp 间距、15 列牌格、细边框、独立行高/字号系数沿用；主内容宽度与左右分配按原浮点参数计算。

v2 设计稿按这些参数自绘新的记牌条，不裁切用户截图冒充实现结果。显示顺序采用用户要求的掼蛋默认顺序，示例数据按牌种对应重排；整体比例用于阅读，真实物理像素仍依赖手机密度、安全区与窗口边界。圆钮与主条分开绘制，圆钮外部不出现矩形底色。

尺寸页的四列八项控件、宽金色轨道、竖条滑块、末端小点，以及牌序页 8 + 7 两行牌块来自用户截图的可见样式。控件的全部原触摸实现尚未逐项恢复，视觉证据不能替代真机行为验证。

正常条不增加阴影、金属金色渐变、状态胶囊或第三个常驻按钮。隐藏恢复沿用「显示」圆钮。等待条保留圆钮加金色两行横条，提示文字按自用场景修改。

## 4. 需求修订

用户否定上一版普通字体的悬浮窗效果，并明确取消出牌纠错。当前 [PRD v2](../design/PRD.md) 和 [四张设计图](../design/review/README.md) 为确认入口；初始手牌编辑、补记、撤销与出牌修改均删除。用户已明确保留 App 自动更新，名称固定为「记牌器」。
