# JPQ 产品方案 · 待设计确认

日期：2026-10-11。状态：范围已确认，以下交互和实现方案待用户确认；此文件不是已完成应用的功能说明。

## 1. 项目目标与输入

实现用户提供「AI 扑克记牌器」在腾讯「大掼蛋」中的记牌效果，复现核心操作体验，用于用户自己的 Android 手机。首版专注大掼蛋，后续可通过游戏适配器和规则配置扩展。

用户已确认：

| 项目 | 确认内容 |
| --- | --- |
| 游戏 | 腾讯「大掼蛋」独立 App |
| 手机 | 小米 17 Pro Max、小米 17 Ultra 徕卡版 |
| 系统 | 澎湃 OS 3/4；实际 Android API、系统构建号及两部手机的对应关系待真机读取 |
| 首版范围 | 完整适配大掼蛋，保留多游戏扩展 |
| 核心功能 | 稳定自动记牌、剩余统计、三家出牌记录、手动纠错 |
| 显示配置 | 炸弹潜力计数标红；牌序按玩法可调；尺寸/字号可调；右侧三家记录可关闭 |
| 交互原则 | 整体交互沿用原 APK；其他改进需先沟通确认后实现 |
| 默认显示参数 | 沿用 APK 内置的两副牌默认参数和布局计算方式 |
| 开始后的等待界面 | 左上角隐藏按钮与金色提示条；稳定识别到牌局后自动切换到记牌条 |
| 自动更新 | 使用用户的 Cloudflare 免费资源；记牌器更新项目与现有项目独立部署 |
| 商业功能 | 去掉会员、收费；按本地个人工具设计 |
| 开发边界 | 先研究、设计，经用户确认后开发 |
| 代码仓库 | https://github.com/cyotun/JPQ.git |

研究输入：参考 APK 1.3.7、首轮七张截图、后续补充的显示配置/等待截图与交互要求、公开 GitHub 项目与 Android 官方文档。已完成静态结构检查、自动反混淆、部分核心方法体阅读，以及随包业务/预处理 Lua 的本地解密与完整性校验；尚未安装运行或完成真机录屏验证。证据详见 [APK 研究](research/apk-analysis.md) 和 [方法研究](research/method-analysis.md)。

## 2. 首版功能与参考软件的对应关系

| 功能 | 来源 | 首版设计 |
| --- | --- | --- |
| 游戏平台选择 | 截图与 APK 配置结构 | 默认大掼蛋；保留平台扩展入口，未适配游戏不宣称可用 |
| 玩法、人数、牌副数 | 截图 | 默认掼蛋、4 人、2 副；其余玩法先作为扩展结构 |

| 自动识别自己的初始手牌 | 截图统计口径与状态类 | 发牌和进贡/还贡完成后锁定初始手牌，支持核对 |

| 游戏顶部横向记牌条 | 截图与用户补充要求 | 深色底、金色按钮；炸弹潜力计数红色，普通计数白色，0 张淡灰 |
| 三家出牌记录显示开关 | 用户明确要求 | 配置中可关闭整个右侧区域；悬浮条缩短，内部记牌继续 |

| 新局自动重置及手动重置 | DEX 状态、策略结构与截图 | 多信号确认新局；手动重置后等待新基线，不直接清空再盲记 |
| 进贡/还贡 | 掼蛋策略类 | 贡牌不作为正常出牌记账；完成后重新建立本局手牌基线 |
| 自己出完后的队友手牌展示 | 用户截图、对家明牌状态结构 | 不把队友手牌当成自己的新手牌，也不错误触发新局 |
| 尺寸和字号调整 | 截图、设置持久化方法及用户确认 | 总宽度、左右比例、牌格高度、记录行高及四项字号；即时预览、保存退出、恢复默认 |
| 牌序调整 | 截图、设置持久化方法及用户确认 | 拖动 15 种牌；掼蛋/斗地主显示预设；自定义顺序按当前游戏与玩法分别保存 |
| 设置导入/导出 | APK 方法名 | 本地文件备份，带配置版本校验 |
| App 自动更新 | 用户新增要求 | 独立 Cloudflare 服务提供版本信息/安装包，检查与下载不影响本地记牌 |
| 撤销、补记、修改出牌 | 用户确认需求；未确认参考 APK 有此完整交互 | 作为首版增强，修改后从事件记录重算统计 |

“完整适配”指下面的标准四人两副牌流程。参考 APK 中「团团转」等变体尚未验证腾讯 App 的具体规则，不能只增加按钮就宣称支持；若实际常用模式包含这些变体，需补充规则与样本后纳入验收。

## 3. 界面与使用流程

界面概念图见 [design-preview.png](design/design-preview.png)。它是设计示意，按钮尚未实现。

### 首页

保留深色、金色的视觉风格。上方显示「大掼蛋 · 本地记牌」，正文包含游戏平台、玩法信息、权限状态和「开始记牌」。底部只保留「记牌」「设置」，不设置账号或会员栏目。

使用步骤：打开记牌器 → 检查悬浮窗权限 → 点击开始 → 系统屏幕共享授权 → 打开/返回大掼蛋 → 等待发牌及贡牌完成 → 核对识别到的 27 张初始手牌 → 自动记牌。

自动初始化通过稳定性与数量校验后直接开始；如数量不符或置信度不足，显示「待核对」，用户可修改。一次采集会话内可以识别多局；采集停止或系统收回权限后需要重新授权。

### 开始后的等待界面

点击开始、采集授权成功但牌局基线尚未建立时，在左上角显示参考截图中的圆形「隐藏」按钮和金色圆角提示条，暂不显示虚假的牌面计数。示意见 [waiting-preview.png](design/waiting-preview.png)。

两行提示文案：

> 进入牌局后，自动开始记牌
>
> 若牌局已开始仍未显示，请检查权限或重新开始记牌

进入房间、发牌及贡牌阶段继续等待；只有识别稳定且基线有效后，才切换为完整记牌条或已配置的仅计数模式。隐藏/恢复沿用原 APK 方式，后台观察继续；若在隐藏期间完成初始化，恢复时显示当前状态。共享权限失效进入对应错误/重新授权提示，不继续显示误导的等待状态。

### 记牌悬浮条

左边：隐藏按钮和 15 种牌的剩余数量；右边：上/对/下三行累计已出与出牌历史；末端：菜单和重置。历史默认使用清晰分组，如 `9、10、J、Q、K`，避免 `101010` 被误读。

配置项「显示三家出牌记录」默认开启。关闭后，隐藏整个右侧区域，包括上/对/下标签、黄色数字和历史文本；悬浮条收缩为“隐藏 + 牌面计数 + 重置/菜单”，不留空白占位。三家识别、扣牌和历史保存继续运行，纠错仍可从菜单进入；再次开启后显示期间完整历史。左右比例、记录行高和右侧字号在关闭时置灰，保留原设置。完整模式与仅计数模式分别记住总宽度，切换不覆盖另一模式的布局。

默认黄色数字表示**累计已出**，与参考截图一致。可切换到「剩余手牌张数」，此时明确显示“剩余”标签；无法确认基线时显示 `—`，不伪装精确数字。

牌面计数完全沿用原 APK 的数量阈值配色，用户已确认王牌也保留原行为：普通点数剩余 4 张及以上为红色，1–3 张为白色；大王、小王各自剩余 2 张及以上为红色，1 张为白色；0 张为淡灰。判定使用最新剩余统计，出牌、撤销或纠错后立即重新着色；如普通牌从 4 张变成 3 张，应由红转白。未知或冲突计数显示 `—`/「待核对」，不标红。

红色属于参考软件的数量提醒，不表示已确定某一家持有这些牌；王牌标红也不等于验证了完整王炸组合。不用不完整花色信息推算同花顺或万能牌补成炸弹。有未解决的漏记或识别冲突时显示「待核对」状态，避免仅靠颜色表达异常。

拖动使用专门手柄；普通展示模式限制触摸范围，避免挡住游戏操作。菜单提供暂停/继续、纠错、显示调整、牌序调整、重置本局、停止记牌。

### 纠错面板

选择玩家及对应出牌 → 修改牌面/数量或删除误记 → 预览修改前后的剩余统计 → 保存。补记时指定玩家和事件位置；撤销以追加修订记录实现，可恢复。自己的初始手牌也可修改，修改后统一重算。

### 设置与权限

显示调整沿用参考软件两页布局：「尺寸调整」「牌序调整」。

「尺寸调整」包含截图中的八项：总宽度、左右比例、牌格高度、记录行高、标题字号、数值字号、计数字号、详情字号。拖动滑块时即时预览，提供保存退出、退出不保存和恢复默认；保存后按游戏、玩法、画面比例与完整/仅计数模式恢复。尺寸有最小可读边界，防止数字被裁切；右侧隐藏时不保留不可见区域的触摸占位。

默认采用已从 APK 方法体中读取的两副牌浮点参数，不从截图的整数百分比反推。总宽度约 115.78%、左侧比例 37.03%、牌格高度 94.62%、记录行高 98.17%；其余字号、原基准布局、44dp 按钮、滑块范围和缩放算法见 [原 APK 默认参数](research/reference-display-defaults.json)。恢复默认回到这套值。

「牌序调整」保持原有拖动 15 类牌、保存退出和恢复默认的交互，按玩法使用以下**默认显示顺序**与已保存的自定义值：

| 预设 | 从左到右 |
| --- | --- |
| 掼蛋 | 大王、小王、A、K、Q、J、10、9、8、7、6、5、4、3、2 |
| 斗地主 | 大王、小王、2、A、K、Q、J、10、9、8、7、6、5、4、3 |

自定义顺序优先，切换玩法时读取该玩法已保存的顺序；恢复默认只影响当前玩法。牌序调整只改变展示位置，点数统计及识别仍对应同一牌种，不改变实际玩法的牌型比较规则。斗地主默认顺序作为扩展准备，不因此宣称已适配斗地主自动识别。

权限页显示悬浮窗、通知和后台运行状态；澎湃系统后台设置入口可能不同，使用实际手机验证过的引导。

## 4. 统计口径与规则

标准牌库：13 种普通点数各 8 张，大王 2 张，小王 2 张，总计 108 张。初始每人 27 张。

对点数 `r`，记牌条的默认剩余值：

```text
手牌外剩余[r] = 完整牌库[r] - 自己本局初始手牌[r] - 其他三家累计已出[r]
```

自己的出牌已经包含在初始扣除中，不重复扣除。自己的手牌重排、选牌、出完牌和显示队友手牌都不改变初始扣除基线。

普通点数按物理牌面统计。级牌和红心级牌保留真实点数/花色；不能把万能牌宣称的组合点数直接从牌库扣除。若游戏画面隐藏了真实牌面，记录不确定项并进入核对流程。

进贡/还贡属于手牌转移，不能作为已出牌减去；基线优先在贡牌完成后建立。团团转等变体的特殊转移规则需单独验证。

## 5. 本地运行与设备适配

识别与统计在手机本地运行，不需要登录或云端识别。按用户新增要求，App 需要网络权限用于 Cloudflare 版本检查与安装包下载；断网或更新服务不可用时，已安装版本继续正常记牌，不上传游戏画面。

必要权限是屏幕共享会话授权、悬浮窗与前台采集服务；通知权限用于状态显示及停止入口。更新增加网络和系统安装授权流程，按实际 Android 条件处理；不承诺绕过系统确认。后台电池设置用于降低被系统结束的概率，不能承诺永不被清理。

适配依据是实际捕获图像和窗口几何信息，不硬编码手机型号对应分辨率。需要验证横屏旋转、屏幕分辨率设置、刘海/挖孔安全区、导航条、单应用共享和整屏共享。澎湃 OS 版本号不等于 Android API 版本。

锁屏、系统停止共享、进程结束后，暂停统计并要求重新授权；若中间遗漏了出牌，只能校正或等待下一局，不能恢复出从未采集的历史牌面。

## 6. 实现方向

拟采用原生 Android Kotlin，首页使用 Jetpack Compose，悬浮窗使用系统 WindowManager。本地视觉流程采用区域定位、牌面识别、多帧确认、出牌事件归属、事件记账与显示。

参考 APK 采用 AI 检测、OCR、多个推理后端和加密 Lua 配置。个人版复现相关行为，首版只选择一套经过样本验证的离线识别路线。技术验证比较 OpenCV 模板/轻量分类与可再分发的轻量检测模型，使用整局效果决定主路线；预留识别接口。详情见 [技术方案](design/technical-plan.md)。

现已可阅读部分反编译核心方法和经校验解开的随包 Lua，可以据此复现记牌、区域归属、阶段处理及显示逻辑。它们仍不等于完整原始工程；未验证模型推理、最新腾讯游戏配置与真机效果。研究材料保留本地，仓库保存结论和实现方案。

## 7. 开发与确认

计划分为：识别样本验证 → Android 采集与悬浮窗 → 大掼蛋完整记账 → 两部手机实测 → 独立 Cloudflare 自动更新与安装包交付。每阶段使用 Git 提交，源码上传指定仓库；验收记录区分实际结果与目标。具体门槛见 [验收方案](design/acceptance-plan.md)。

自动更新候选方案为独立 Worker 加独立安装包存储，项目名、域名、存储与发布流程均和现有项目分开。现有 Cloudflare 服务类型与免费资源启用状态尚待确认，不自动升级套餐或启用收费服务。更新检查/下载/安装时机先按 [Cloudflare 更新方案](design/cloudflare-update-plan.md) 讨论后实现。

**本次请求用户确认的设计：**

1. 默认沿用参考软件深色、金色的顶部横向记牌条，炸弹潜力计数标红；三家“累计已出”默认显示，可在配置中关闭。
2. 自动识别与自动新局处理，保留手动重置，并增加撤销、补记和纠错。
3. 标准四人两副牌先完整适配；变体按实际使用模式补充样本与规则后增加。

用户后续明确提出的四项显示要求均已纳入此版：计数按炸弹潜力着色、牌序按玩法调整、大小和字号调整、右侧记录开关；不再将整行计数绘制成红色。

默认参数、等待界面和整体交互也已按用户补充要求纳入。功能汇总示意图不代表合并原软件的「尺寸调整」「牌序调整」两个页面。除用户明确要求的扩展外，新的交互建议单独提出、确认后实施；手动纠错的具体入口和操作也要结合原软件研究后确认。

确认后开始应用开发。后续真机验证还需要读取大掼蛋版本/包名、实际 Android API，以及包含发牌、贡牌、正常出牌、自家出完和结算的游戏样本；这些资料用于识别适配，不需要现在就完成全部准备。
